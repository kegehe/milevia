## 1. 交付范围

CLI 清单复用 `agent_catalog.go`，目前是 Claude Code、Codex、CodeBuddy、Qoder、OpenCode、Cursor。托管的调度、实施和独立审查角色均应可以选择已经安装、已登录且通过角色能力核对的 CLI，允许三个角色使用不同 CLI。不再另维护一个只含 Claude/Codex 的托管清单。

环境清单复用 Runner 注册表和项目目标环境解析：Windows 本机、WSL、本机 Linux/WSL 服务环境、SSH 远程环境，以及项目已有的 WSL→Windows 互操作路径。新增 Runner 依照相同协议接入。本文不把当前没有实际登记和执行适配的操作系统宣传为已经支持。

“全部支持”覆盖现有 CLI 与目标环境组合中，工具本身能够运行的组合。未安装、未登录、CLI 本身不支持目标操作系统等情况需展示具体原因，不能静默切回另一台机器、另一套登录或 Claude。CLI 管理面已有探测或安装入口，不等于该组合已经具备完整项目执行能力；普通 Runner 的缺口也要纳入本次清单，不能以“托管复用现有 Runner”为由跳过。

复用现有 CLI 管理的安装路径、命令别名、版本、登录、模型、认证档案和项目路由，不额外强制填写 API Key。CLI 不支持平台认证档案时继续使用该目标环境自己的登录及配置，页面说明来源；不能将这种 CLI 从托管选项中排除，也不能显示一个保存时必然失败的档案选择器。

本次兼容不包含自动提交、推送、发布、自动回滚、同一目录并行实施或跨项目扩大任务集合。手机 App 的入口和远程控制链路属于单独的客户端接入工作，不能用桌面页面的窄屏布局测试替代。

## 3. 架构选择

采用“现有领域调度 + CLI 适配器 + 目标环境执行服务”。保留已验证的任务、预算、计划、证据、租约、幂等和最终验收逻辑，拆除其中的平台与工具绑定。

不采用为每种 CLI 复制一套托管闭环：会重复维护暂停、恢复和验收门禁，产生不同工具下行为不一致。也不将调度统一改为额外 API 调用：这会改变用户已有认证方式，并不能解决远程目录和进程恢复问题。

### 3.0 复用边界与适配数量

CLI 适配器只处理该工具的参数、权限、输入和输出协议，环境适配器只处理目标侧文件、进程、连接与资源。两者通过统一启动规格组合，不能为每个“CLI × 环境”另写一套调度器或执行器。实现规模应主要随 CLI 数量与环境数量之和增长，真实兼容验证仍需覆盖实际组合，不能因此省略组合测试。

复用 `agent_catalog.go` 和现有探测、安装、登录、档案选择、SSH连接、SFTP及WSL桥接；将已有 CLI 参数构造和事件解析中可共用的部分抽成纯组件，普通会话与托管按各自权限调用，不复制后长期分叉。`AgentRunner.Run` 当前不提供托管需要的持久执行身份和资源收敛承诺，不能直接把其返回成功作为完成。

现有 `RunnerAgent` 负责认证与额度准入，先通过组合接口增加执行协议，不改写为另一个同名通用代理；其已有凭据和额度职责继续保留。目标侧组件只记录执行事实，不独立规划任务或再次决定任务验收。CLI 管理、普通项目会话和托管最终应使用同一组环境解析与程序选择事实。

### 3.1 控制服务

控制服务是会话、任务认领、预算、要求版本、派发意图、证据与最终验收的唯一业务事实来源。调度角色只返回领域动作，服务端校验后执行；CLI 自称完成或退出0均不能直接写任务 done。

每个已启动执行冻结 `runnerId`、环境身份、CLI 及实际路径/版本、认证引用、角色、协议版本和输入指纹。切换配置需先暂停并确认资源结束，只作用于后续执行，不能使旧执行回调获得新授权。

默认三个角色都使用项目目标环境的 CLI 和该环境的认证来源。本次“混合 CLI”不等于同时开放各角色任选不同机器；跨角色任意选择执行环境暂不增加，避免无必要地引入跨端凭据、路径和配置组合。项目本身可以位于任一已支持环境，全部环境的兼容目标保持。

### 3.2 CLI 适配器

各适配器负责：目标侧程序解析、版本及能力探测、角色权限配置、标准输入、正常输出与过程事件、结构化结果、失败分类、用量和取消。三个角色共用调用协议，角色提示词和结果校验各自独立。

不把 Claude 的参数照搬给其他 CLI，也不只靠提示词声明“没有工具”。保留调度不实施代码的要求；适配器需提供有效的工具禁用或权限隔离方式，并报告实际权限。遇到上游 CLI 不能满足角色约束，需明确实现替代隔离方案及验证，登记为兼容缺陷，不能据此永久缩小“所有 CLI”的目标。

“调度不实施”是职责和权限要求，不能不加判断地等同于“每种 CLI 必须原生支持与 Claude 一样的空工具参数”。优先使用已核对的无工具模式；否则验证隔离的只读角色运行方式。两种方式下，实施角色仍返回既有结构化文件编辑，由目标执行服务按范围和原始哈希应用；本次不同时引入 CLI 直接修改项目目录的另一条实施链路。普通 read_only 标志、禁工具模式和操作系统隔离的保障分别声明，不互相冒充；进程回收容器也不被当作文件或网络沙箱。

隔离只读方式必须满足主方案的“受控资料输入、无任意执行能力”约束，不能直接将实时项目目录挂给 CLI 后声称满足。角色只接收本工作项已授权且绑定输入指纹的不可变资料包，包括必要源码、基线、规则及证据；额外资料通过领域 `read_context` 等动作核对版本后重新派发，不能旁路读取实时项目。排除凭据正文和其他无关任务资料，沿用输入大小限制与截断标记。CLI 的登录及模型 API 通信仍由其认证通道使用，不把认证文件作为模型可读资料，也不因此要求禁止正常模型通信。

不能向角色开放任意 Shell、项目 MCP、hooks 或其他可产生项目及外部副作用的入口。只读文件系统本身不足以满足这一条件；需要额外隔离的适配器必须实测其权限边界，未做到时如实标记兼容缺陷。检测到工具调用后取消只用于发现异常，不能替代执行前的权限限制。调度、实施和审查的输入均绑定各自工作项快照，避免“不能写但读到了新源码”导致结果与证据引用的版本不一致。

过程事件规范化为角色启动、正常输出、诊断、用量、结果和执行结束；保留脱敏的原始事件用于诊断。各 CLI 事件不能伪装成 Claude init。无最终结果、输出截断、工具越权、协议不匹配或授权过期均进入已有纠正或失败路径，不生成成功证据。

### 3.3 目标环境执行服务

快照采集、规则读取、受控写入、CLI 启动、验证、进程查询与停止、产物读取在目标侧实现统一协议。本机直接调用；WSL 和 SSH 通过各自桥接调用同样的执行服务。原有跨端探测和连接管理负责找到目标，不作为持久执行服务的替代品。

“服务”指执行职责，不要求每个目标新装一个系统常驻服务。本机优先使用同进程实现；跨端复用现有连接按需启动带版本的用户级辅助程序。辅助程序可分为短连接协议入口和执行期间存活的监督进程：SSH连接断开不能连带销毁执行事实，重新连接须能查询同一工作项。监督进程仅在运行、输出或结果待确认时保留，持久执行回执另按恢复与去重规则保留；默认不要求root、sudo、系统服务管理器或对外开放新的监听端口。辅助程序从受校验的构建产物部署到目标用户数据目录，不落入项目源码，不从未知地址临时下载执行。

优先使用同一份目标执行核心，按平台编译；传输只负责请求和响应。健康检查记录协议、目标身份、辅助程序版本及实际进程管理能力；不兼容版本不能接管正在运行的工作。新版本先并存，已启动工作继续由原版本监督；确认无活动资源后才允许清理旧程序，不能原位替换活动执行所依赖的文件。代码实施记录需给出辅助程序体积、启动成本和各目标部署/升级/清理验证，不能仅描述接口。

跨端请求使用版本化结构化输入，不能将模型文本、源码内容、凭据或 JSON 直接拼入 Shell。复用现有连接与目标侧登录；不把本机认证目录复制到远端，不把明文认证加入命令行、事件或数据库回执。

执行服务保存工作项幂等键和实际执行身份。重传同一启动请求只能返回已有身份；SSH/WSL 管道断开属于连接状态未知，不能当作远端未启动或已经退出。重连先核对事实，再决定继续观察、停止或交还处理，不重放旧执行。

跨端协议至少覆盖能力/健康、快照/源码、受控写入、准备/启动、状态查询、过程回读、取消、授权续期、最终事实确认和资源释放。控制请求携带目标身份、会话与工作项、执行ID、尝试次数、所有者代际、授权版本、输入摘要和预算；不是每次重连重新产生执行ID。同一执行ID的不同执行规格必须拒绝，旧代际请求也必须拒绝。续期、撤销和查询是独立控制消息，不通过更改原启动规格表达。

授权令牌、租约续期和代际更新只走可信控制通道，不进入角色提示词或CLI的模型输入；模型返回的工作项ID、权限字段或授权自述不能更新执行授权。目标复用已有连接认证并核对控制者归属，不允许匿名进程仅凭执行ID接管、取消或续期其他会话。

启动按“控制端持久化意图→目标持久化准备及启动身份→受控启动→目标持久化事实→控制端消费回执”进行。目标须在允许进程实际运行前建立可恢复的身份/资源归属。已记录启动意图但无法证明进程是否启动的状态返回未知并保留保护，不能当作不存在后重启；PID必须同时核对出生标识和所属资源，避免PID复用。网络请求允许重传，以目标侧去重和控制端幂等消费实现可恢复行为，不承诺网络条件下任意外部副作用天然只发生一次。

消费回执不能立即删除目标侧的执行ID、请求摘要和终态去重记录，否则晚到的旧启动请求可能再次执行。完整日志和产物可以按预算清理，轻量去重记录需保留到相关会话结束、旧授权全部失效且旧代际请求仍能被拒绝之后；清理条件由两端协议明确，不能只按进程退出时间定时删除。

授权采用带代际的有限租约，目标使用本地计时约束有效期和剩余执行预算，不能单靠控制端内存中的取消函数。连接丢失后不派发新动作；运行中的调用最多持续到授权或预算先到期，目标监督负责停止并保存实际结果。停止请求只有目标确认静默后才显示为已停止；断线时可显示“停止已请求，等待目标确认”，不假报成功。新控制者必须先核对旧执行并使旧授权失效，不能只抢到数据库租约就启动第二份工作；计时或目标重启后无法证明旧授权有效时按未知/过期处理，不能自行延期。

目标侧写入仍核对选中任务、会话和目录所有者、代际、要求/计划版本、原文件 SHA-256、修改范围、规则与排除策略。控制服务的本机文件操作不能代替远程原子校验。

过程事件携带执行ID和目标侧单调序号，落盘后再提供回读。控制端按该身份去重并保存回读位置，重连续读不能重复拼接正文或漏掉完成事件。输出及产物保留有界缓存、会话存储预算和明确的截断/缺失标记；缓存满、磁盘不足或回读位置已被清理必须显式失败或报告缺口，不能无限堆积，也不能用剩余片段拼成完整成功证据。

### 3.4 环境身份与目录保护

资源键使用目标执行身份与目标侧规范路径，不能仅以 Runner 显示名称区分。同一 SSH 主机的多个连接、WSL UNC 与 Linux 路径、`/mnt/c` 与 Windows 路径可能指向同一目录，需要建立身份或保守互斥；不能因路径写法不同而并行写入。

主方案已有的普通会话、终端、项目命令和Git等平台管理写入口也必须遵守同一目标侧保护，不能只有托管调用辅助程序、普通SSH/WSL调用却绕过门禁。同一目标被多个控制服务连接时仍需目标侧核对归属；目标锁被占用或无法证明共享路径归属时明确阻塞，不依据控制端各自的本机数据库独立放行。

暂停、停止或重启后，只有确认目标侧执行、输出读取、快照和写入均静默，才可交还目录及任务。Windows Job、Linux/WSL 的进程生命周期机制各自核验；不能声称一个平台的普通进程组具有另一个平台容器完全相同的能力。

阶段B应先实测目标侧监督能力，包括子进程脱离原进程组、父进程先退出、目标监督崩溃及环境重启。普通SSH信号、关闭管道或kill进程组不作为“全部后裔已结束”的单独证明；缺少可靠收敛条件的环境保留兼容缺口及目录保护，不假报停止，也不自动提权、关闭系统保护或修改主机安全配置来伪装支持。

进程存在但连接丢失时保留保护；不能因控制服务 PID 已不存在而释放远端目录。目标身份改变、执行记录丢失、目录被替换或结果无法核验时进入需要处理，保留成果和历史。

目标安装ID不单独作为物理目录身份：同机不同用户、多个SSH连接、重新安装辅助程序可能仍指向同一资源。分别记录连接身份、执行宿主身份、文件系统/目录身份和所有者代际；可以证明共享的路径进入同一保护域。无法可靠区分的别名不能乐观地放行并发，而应保守串行或要求建立映射。不能假设Windows与WSL、不同挂载方式的文件锁必然互通。

文件路径和范围判断使用目标文件系统及实际目录的语义，不能依控制端的 `runtime.GOOS`、`filepath.Abs` 或全局转小写推导远端事实；同一操作系统不同挂载或目录也可能具有不同大小写规则。协议使用明确的项目内相对路径形式，由目标解析并核对真实路径、大小写、保留名、链接及权限。不能把 Linux 的 `A.go` 与 `a.go` 合并，也不能隐式改写 Unicode 文件名；无法无歧义表示的路径明确拒绝并说明原因。目录互斥、源码清单、Scope、差异和写入去重使用同一套目标语义。

快照指纹包含采集策略版本及必要的目标文件系统语义；源码、规则、基线和验证证据引用一致的指纹定义。快照在目标侧执行既有的变化检测及完整性核对，不能把一次 SFTP 复制成功当作一致快照。策略变化按显式迁移失效旧证据，不能将新旧算法的结果混用为同一版本。

控制端计划与验收不下沉到目标。目标重连回报的已完成结果需要控制端按当前授权、要求/计划、源码及环境重新核对，不能由远端自己把任务置为done。目标租约失效后的结果可保留为历史，是否能作为新验收输入仍由原有领域规则决定。

### 3.5 测试与浏览器

测试命令、解释器、依赖及敏感配置哈希在项目目标环境核对。WSL 项目不运行 Windows 的 npm shim，SSH 项目不在电脑副本上运行测试。实施前基线、失败重跑、证据失效、独立审查和最后同快照验收继续遵守既有规则。

浏览器优先在目标侧启动独立服务和浏览器，保存报告与截图。若使用控制端浏览器，必须建立绑定该工作项的受控转发，记录目标服务和浏览器两端环境并回收自有资源；目标的 localhost 不能直接当成控制端 localhost。缺浏览器能力只影响需要浏览器验收的任务，不能阻断无关任务。

### 3.6 控制乱序与预算核算

所有者代际只解决控制者更换，不能代替同一控制者下的暂停、停止和授权变更。增加持久的会话授权版本及撤销水位；暂停、停止、立即生效的要求变更和预算收紧等改变授权时，控制端先事务记录意图并禁止不再合法的新派发，再向目标传播。目标即使还没见过某个执行ID，也必须记录已认证的撤销，不能以“未找到进程”结束处理；晚到启动、写入和续期不能复活旧授权或覆盖更新的限制。普通日志、心跳和不涉及权限的状态变化不递增授权版本，也不因此中断合法执行。

目标将授权核对与实际启动/单文件写入置于同一受控操作边界，避免检查通过后又被已生效的撤销穿透。已进入的单文件原子操作允许完成收口，撤销后不再进入后续文件操作。乱序控制按授权版本处理，旧续期不能清除暂停/停止。恢复时可保留逻辑工作项，但须先核对旧尝试静默，再给新尝试当前版本的授权；不重新启用旧请求。延后要求继续遵守主方案的待生效语义，不误杀允许收口的当前回合，也不能继续派发相关的新回合。

控制端受理不等于目标已经执行。断线时旧执行最多持续到旧授权或预算到期；页面分别展示“已受理、等待目标确认”和实际生效事实。立即要求先停止旧执行并确认收敛再启用，不能一边显示新要求已经生效一边继续消费旧授权成果。停止确认同时证明无旧执行及可迟到复活的旧授权，不能仅依一次进程列表为空。撤销水位的清理与旧授权、旧消息可拒绝条件绑定，辅助程序重启也不能丢失。

预算预留、消费和工作/最终验收份额仍由控制端账本统一核算，目标只执行授予的上限。启动确认丢失不自动退款或重新扣一份；用执行ID及累计用量水位幂等核对，重复事件不能重复计费。续期、重连和恢复不重置单轮起点、会话剩余额度、尝试及修复次数，也不改变已冻结的预算类别。目标截止时间取授权租约、单轮期限、会话剩余授权和检查超时中最早者；重启后无法恢复可靠计时则停止并核对，不重新给满额。

减少预算时传播新的约束，页面明确目标是否确认，不能承诺失联执行已立即采用新上限；增加预算也不能重启被暂停的工作。CLI 不提供精确 token 或金额用量时标明估计/不可得，不能宣传精确费用硬限额。目标日志、资料和产物受空间预算约束，并预留终态记录与清理空间；不能耗尽磁盘后仍宣称可可靠保存执行结果。停止及资源清理由服务完成，不依赖剩余模型调用额度。

### 3.7 受控写入与部分完成恢复

复用现有 mutation journal 的领域语义：每批写入有稳定 mutationID、所属执行ID和不可变批次摘要，目标在写入前持久记录；逐文件记录原/目标内容哈希、创建/删除、必要权限与处理事实，完成后保存实际输出快照。单文件替换按目标平台提供原子写入及恢复核对，不能将“原子校验”误称为整个多文件批次全有或全无。

在第几个文件后断线、崩溃，或文件已替换但回执未写下时，均先按原 journal 查询并核对实际文件。能证明的事实才更新回执；无法证明整批完成时保留部分成果并标记未知/需要处理，不盲目重放整批、不覆盖用户后续修改，也不自动回滚。进程及写入已经静默、仅结果未知时，仍可按主方案进行受控只读诊断或明确停止交还，不把结果未知等同于目录永久不可释放。

快照、受控写入、进程启动和目录交还共用目标侧目录保护，不能因网络调用返回就释放。控制端以持久意图、目标事实和短事务消费衔接，不能跨网络持有 SQLite 事务等待。撤销与单文件操作的先后遵守 §3.6；重试使用原 mutationID 查询，任何新的修复必须在确认静默、重新核对当前快照及预算后生成新的授权工作项。

### 3.8 最终验收与资源交还

最终验收复用主方案的统一提交及 releasing 状态，不另建通用分布式事务。控制端先持久化 finalizationIntentID，绑定拟通过子集、预期业务/授权版本、要求与计划、源码/规则/环境指纹、证据水位和依赖事实；目标在自有验证资源收敛且目录仍受保护时，重新采集最终事实，持久返回同一意图的可核对回执。目标在交接期间不接受新的写入或执行，连接断开、租约到期也不能自行交还目录；失效控制者及旧授权仍不能接管。

控制端取得回执后，用短事务按当前事实再次核对上述绑定和依赖闭包，执行版本比较后提交 Task.done、TaskEvent、会话终态及 releasing。期间暂停、补充要求、预算、依赖或已观察到的代码/环境变化导致门禁不再满足时，不得消费旧回执完成验收，按领域规则停止或重新核对；目标自己的“通过”不能替代该事务。网络往返不放入数据库事务，回执丢失只查询同一意图并幂等消费，不重复提交事件或重跑整个任务。

业务验收与资源交还分别记录和展示。事务提交后向目标幂等交还，确认静默、目标保护已释放后才完成控制端认领/目录释放；断线保留 releasing 并在恢复时补查，不假报目录可写，也不重开终态调度。目标交还回执和撤销水位继续按协议保留，迟到启动不能在释放后复活。最终证据绑定稳定采集的快照时点；采集中发现变化则不验收，不承诺阻止平台外的编辑器在验收后继续改文件。

## 4. 能力展示与页面

项目能力响应由 Runner 和 CLI 目录生成，区分：目标是否可达、工具是否安装/登录、角色是否支持、受控进程是否可用、快照/写入/测试是否可用、浏览器是否可用、认证来源与具体不可用原因。

能力探测须有缓存、超时和明确的“正在探测”，避免 WSL 冷启动或 SSH 断线拖住页面。页面展示能力与启动时复核使用同一判据；页面先前可用不代表之后无需复核。

能力至少分为工具自身不支持、环境缺失/不可达、未安装/未登录、适配待实现、适配已实现待真实验证、验证通过；将状态与具体原因分开保存。缺少测试环境不能被写成兼容通过，也不能永久从清单隐藏。能力缓存按目标身份、CLI实际路径/版本及协议版本分组；CLI升级、重装、切换环境或配置后失效。不能因为命令名称未变，就采信另一版本的权限和事件协议。

用户继续选择任务和预算，默认使用项目环境及已有 CLI 配置。角色允许不同 CLI；不支持平台档案的工具显示目标侧 CLI 配置，不提供虚假的档案/思考强度选项。过程页显示实际执行环境、CLI、模型、角色与认证来源，保留原有计划、证据、控制和问题回答。

## 4.1 升级与既有会话

旧会话保留原有CLI、环境、启动基线、计划、预算用量、事件及证据。未结束的旧Windows Job执行仍由原适配器核对和收口，不在升级时改派为通用执行或重放启动。没有目标执行身份、协议或代际的旧记录不能凭空补为已授权的新执行。

先增加可兼容读取的数据字段和适配接口，再迁移新创建/明确恢复的会话；生产读取未知协议时明确暂停处理，不能忽略新字段继续执行。旧证据不因新增兼容能力而自动升级为其他工具/环境的证据。数据库升级先在副本验证恢复与回读；回退程序只有在确认能理解当前数据和无活动新协议执行时使用，不承诺任意旧版本可直接回退。

以下是内部依赖顺序，不是将后续环境和 CLI 移出交付范围；尚未验收的组合必须一直标记待完成。

## 6. 验收矩阵

按实际登记环境 × 六种 CLI 维护逐项结果，至少包含 Windows、本机 Linux/WSL、Windows→WSL、WSL→Windows 和 SSH。工具自身不支持的操作系统组合记录来源与原因；未安装不等同于适配通过，具备环境后仍须联调。

每个可运行组合至少验证：

1. 三项独立任务和一项依赖任务，覆盖新增代码、已有实现核查与真实失败修复。
2. 调度、实施、命令测试、独立审查、最终同快照验收及过程回读；不能只测 CLI 退出0。
3. 混合角色 CLI，共享同一项目事实且按各自登录/配置执行，不擅自回退工具。
4. 用户暂停、停止、预算到点，确认目标侧进程与输出结束，停止后不自启。
5. WSL/SSH 断线、恢复、启动回执丢失、重复启动请求、控制服务和目标执行服务重启，不重复实施或测试。
6. 目标目录或规则改变、依赖和.env改变，旧证据失效、等待状态能发现变化。
7. 浏览器任务的真实交互、断言、报告、截图、端口归属与清理；同时检查无关任务继续推进。
8. CLI 管理中的路径、别名、模型、登录和认证选择与实际执行一致；无平台档案的 CLI 仍可使用。
9. 目标不可达、CLI 缺失/未登录、协议版本不同、权限能力缺失、输出不完整均有可解释结果，不误记完成。
10. 控制端失联和租约到期、旧代际晚到启动/写入、准备后崩溃、真实启动后回执丢失，均不能启动第二份执行或错误释放目录。
11. 过程断线续读、重复事件、缓冲区满、产物超限和已清理游标，不能重复正文、丢失终态或伪造完整证据；旧会话与活动旧版本执行可核对、停止及回读。
12. 同一控制者下取消先到、启动后到，续期与暂停乱序、立即/延后要求及降低预算、暂停后恢复，旧授权均不能复活；已停止会话拒绝恢复，UI区分控制已受理与目标已生效。
13. 多文件批次中断、文件替换后回执丢失、期间用户再次改动，按 journal 核对部分成果，不整批重放或回滚；撤销与单文件替换交错后不再写后续文件。
14. 重复启动确认/用量事件、续期重连、预算减少和目标重启，不重复扣费、不退款重发、不重置时间/尝试/修复次数，也不挪用最终验收份额；空间不足保留明确失败事实。
15. Windows控制Linux的大小写双文件、Linux控制Windows的实际目录语义，以及Unicode、分隔符、链接和权限变化，路径/范围/快照/写入一致；采集中改动不能生成稳定快照。
16. CLI隔离方式不能读取未授权实时源码或凭据资料，不能经Shell、MCP、hooks产生副作用；输入版本变化后旧结果不能被当作新快照证据，正常认证及模型通信仍可用。
17. 最终事实回报后发生暂停、要求/预算/依赖变化、消费确认丢失或目标释放确认丢失，不能错误写done、重复事件或提前交还目录；终态恢复只补交还，不重开执行。

领域替身、编译检查、CLI真实测试、浏览器测试和完整端到端结果分别记录；不能用替身或 Windows Claude 的结果代替其他组合。一次只有一个任务运行通过，不能作为多任务托管验收。

回归分层运行：公共领域不变量、单CLI协议、单环境执行协议、CLI与环境交叉组合、真实多任务端到端分别记录。日常修改运行受影响层和已有回归；首次开放某组合及协议/权限/环境改造后必须完成相应真实全流程，不要求每次文案修改重跑所有付费模型。测试模型调用与测试资源同样受预算约束，环境不足时保留待验证状态，不将其填成绿色通过。

## 6.1 本次方案复审结论

核心三层架构适合当前项目，已有领域模型与Runner基础能够复用。前次补齐目标组件、断线授权、可恢复启动、事件续读和迁移后，本次继续发现同一控制者的控制乱序、远程部分写入、预算重复核算、目标文件系统语义、只读输入与最终验收交接仍缺少明确规则，已补充到 §3.2、§3.4 及 §3.6—§3.8，并增加验收矩阵第12—17项。这些是对已有领域约束的跨端落实，不增加每机系统常驻服务、每组合一套执行器、角色任选机器或CLI直接写项目等额外链路。

这是一份针对当前代码和需求较稳妥的实施方案，不是所有工具权限及远程生命周期已经得到验证的证明。实施前先以阶段B的跨CLI、跨环境闭环核实关键协议；发现上游CLI能力或目标平台约束时修正适配细节，保留全部既有环境与CLI的交付目标，不用文档承诺代替实际兼容。
