# 建议分析的 Codex 提示词传递修复

日期：2026-10-27

## 原因与证据

Windows 本地运行器把多行 prompt 作为 argv 传给 `cmd.exe /d /c codex.cmd`。
npm 的 `.cmd` 通过 `%*` 转发参数时，prompt 从第一个换行起被截断。
模型虽然能看到项目工作目录和输出 schema，却收不到完整分析要求、历史去重清单、候选列表。

本机 2026-10-19 的两次扫描分别收集了 5 条、3 条候选，核实阶段漏回 4 条、2 条，最后各新增 1 条。
原始 Codex 会话中的核实任务确实只有开头一句，曾返回“未提供核验对象或核验标准，无法执行”。
此前的兜底逻辑在重试仍漏项时，把没有核实结论的候选转换为 `confirmed=false`，并将扫描标记为完成，进一步掩盖了传参故障。

## 修复

- 本地 Codex 的 `exec` 和 `exec resume` 使用 `-` 读取 stdin，完整 prompt 不再经过命令行。模型、权限、schema、MCP 参数保持原有传递方式。
- stdin 由 `os/exec` 并发复制，避免长 prompt 与 stdout/stderr 读取互相阻塞。取消运行与收到终态都会回收进程，解决取消分支未执行终止的问题。
- 核实结果合法但漏项时，保留已有正、负结论，仅将漏项交给新会话，使用局部编号核实后映射回原候选。
- 跨批次返回时同时转换映射键和结论内部的编号，避免批内编号与全局编号不一致。
- 编号重复、越界、缺少 `confirmed` 等不能可靠归位的结果，重验整批；每批仍最多重试一次。
- 重试后仍不完整则明确失败，不再把未核实候选当作问题不成立，也不发布本轮不完整结果；既有建议不受影响。
- 分析与重试提示词明确全项目覆盖、逐模块取证及独立会话上下文；移除“最少只报 1 条”和假定已记住上轮分析的引导。工作区状态、分析进度及只读权限导致测试无法执行，不应替代具体发现或核实依据。

## 回归验证

`codex_runner_test.go` 使用实际子进程和 `.cmd` 的 `%*` 转发测试 stdin，测试过程不调用模型。
覆盖新会话、续聊、LF/CRLF、中文与 emoji、shell 特殊字符、超过命令行长度限制的文本，以及真实的发现/核实/修正提示词。
另验证 CLI 不读取 stdin 时仍能取消并回收进程。

`insights_verification_test.go` 覆盖遗漏候选补验、乱序与局部编号映射、保留明确的否定结论、重试后仍漏项报错，以及重复/越界/缺失字段时整批重验。

```powershell
cd apps/control-server
go test ./internal/app -run 'Test(.*Insight.*|.*PassB.*|Codex.*|ReadCodex.*)$' -count=1 -timeout 10m
go test ./... -run '^$' -timeout 90s
```

2026-10-27 本机 Windows 验证结果：相关回归 223 个测试及子用例通过，7 个平台相关用例跳过，0 失败；控制服务所有包的编译检查通过。

同日复审补充：新增四条候选全部 16 种漏项组合，首轮与补验结果均使用逆序，验证正负结论及编号归位。Windows 下对 stdin 传递、阻塞取消、终态回收与核实补验执行 `go test -race`，通过且未报告数据竞争；`go vet ./...` 通过。复审未修改生产代码。

这些测试验证传参完整性与处理逻辑；模型实际会产出多少建议，仍需使用修复后的桌面端重新分析比较。无需修改或清空用户历史建议。

变更保留在工作区。当前已安装的桌面端不会自动加载 Go 源码，需要重新构建相应控制服务或桌面端后生效。
