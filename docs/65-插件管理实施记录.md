# 插件管理实施记录

日期：2026-11-12  
路由：`/plugins`（首页顶部「插件」入口）  
后端：`apps/control-server/internal/app/plugin_manager.go`  
前端：`apps/web/src/pages/PluginsPage.tsx`（样式 `plugins.css`）

## 1. 目标与边界

目标：在 Milevia 里完成插件的**发现、安装、启停、升级、卸载与市场管理**，并让对话页的
「插件」技能来源与真实启用状态一致。一期做完，不分阶段。

两条边界：

1. **CLI 是唯一事实源。** 插件列表、启用状态、安装范围、版本、市场全部来自各 CLI 自己的
   子命令与 JSON 输出。Milevia 不定义插件格式、不自建市场。
2. **不替用户确认。** 安装过程中若市场声明了待执行命令，服务端把命令与 sha256 返回给前端，
   用户确认后才以 `--accept-command <sha256>` 重试。绝不自动追加 `-y` / `--yes`。

插件本身就是 CLI 的扩展包：一个清单（`.claude-plugin/plugin.json` 等）加上技能、命令、
代理、钩子、MCP/LSP 服务。安装插件等于让 CLI 执行这些内容，因此市场来源与待执行命令都要
让用户看见。

## 2. 支持范围

| 工具 | 列表/详情 | 安装/卸载 | 启用/禁用 | 升级 | 市场 |
|---|---|---|---|---|---|
| Claude Code | ✅ | ✅ | ✅ | ✅ | ✅ |
| Qoder | ✅ | ✅ | ✅ | ✅ | ✅ |
| Codex | ✅ | ✅ | —（CLI 无子命令） | — | ✅ |
| 其他（Cursor / CodeBuddy / OpenCode） | 只读磁盘扫描 | — | — | — | — |

能力位由 `GET /api/runners/{runnerID}/plugins` 的 `capabilities` 返回：服务端先按适配器给出
默认值，再尝试 `plugin --help` 收缩；前端只渲染为 true 的动作。收缩只针对依赖子命令的动作，
`details` 由适配器在本地补全（清单路径、组件数），不参与收缩——Qoder/Codex 的帮助里没有
`details` 子命令，但详情仍然可用。`capabilities.scopes` 给出该 CLI 真正支持的安装范围
（Claude/Qoder 为 user/project/local，Codex 只有 user），前端据此生成范围选项，并拒绝把
Codex 的全局安装显示成"项目范围"。

同一条插件 ID 可以同时存在于多个范围（实测 Claude 的 `rust-analyzer-lsp@claude-plugins-official`
同装于 user 与 project）。列表记录因此额外带 `key = id|scope|projectPath`，前端用它做 React key
和操作定位；详情/启停/升级/卸载再带上 `scope` 与 `recordProjectPath` 消歧，服务端用
`findPluginRecord` 选中正确记录。

已在 2026-11-12 本机核对过实际命令（Claude Code 2.1.x、Codex 0.161、Qoder 1.1.x）：

- Claude：`plugin list --json [--available]`、`plugin details <name>`（文本输出）、
  `plugin install <id> --scope <user|project|local> [--marketplace m] [--accept-command sha] --json`、
  `enable/disable/update/uninstall --scope … --json`、`plugin marketplace add/list/remove/update`。
- Qoder：`plugins list --json [--available]`、`plugins install/uninstall/enable/disable/update --scope …`、
  `plugins marketplace add/list/remove/update`。
- Codex：`plugin list --json`、`plugin add <plugin[@market]> [--marketplace m]`、`plugin remove`、
  `plugin marketplace add/list/remove/upgrade`。Codex 市场是全局配置，`marketplace add` 没有 `--scope`。

## 3. 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/plugin-agents` | 插件页可选工具（`managed` 区分可管理与只读） |
| GET | `/api/runners/{runnerID}/plugins` | 列表、能力位、市场；`?available=1` 附带可安装项 |
| GET | `/api/runners/{runnerID}/plugins/{pluginID}/details` | 组件数量、token 开销、清单路径 |
| POST | `/api/runners/{runnerID}/plugins/install` | 安装；`needsConfirmation` 时带 sha256 重试 |
| POST | `/api/runners/{runnerID}/plugins/{pluginID}/enable` | 启用 |
| POST | `/api/runners/{runnerID}/plugins/{pluginID}/disable` | 禁用 |
| POST | `/api/runners/{runnerID}/plugins/{pluginID}/update` | 升级 |
| DELETE | `/api/runners/{runnerID}/plugins/{pluginID}` | 卸载 |
| POST/PUT | `/api/runners/{runnerID}/plugin-marketplaces` | 添加 / 刷新市场 |
| DELETE | `/api/runners/{runnerID}/plugin-marketplaces/{name}` | 移除市场 |

所有接口都带 `agentId`；项目范围另带 `projectId`，由服务端解析项目路径并校验 runner 一致。
详情与写操作还接受 `scope` 与 `recordProjectPath`，用于在同 ID 多范围安装时选中记录。
插件 ID 经 URL 路径传递时由前端 `encodeURIComponent` 编码，服务端用 `pluginPathParam` 做
百分号解码（chi 在 RawPath 上匹配且不解码，漏这一步 `%40` 会查不到）。
执行环境与 CLI 管理页一致：本机 / WSL / SSH，复用 `crossEnvironmentFor` 与
`crossManagedPathPrefix`，WSL 的 UNC 项目路径会转换成发行版内路径。

## 4. 安全与确认

- 安装请求在服务端校验插件标识（非空、≤512 字节、不以 `-` 开头、无换行/NUL）。
- 市场来源与市场名称同样校验（移除/刷新市场走 URL/请求体里的名称）；项目范围必须有项目。
- Codex 的安装与市场是全局配置：服务端按 `capabilities.scopes` 拒绝非 user 范围，
  不会出现"选了项目却装到全局"。
- 写操作经 `pluginMutationMu` 串行化，避免两个请求同时改同一份 CLI 配置。
- 市场声明的待执行命令只在 `needsConfirmation` 响应里出现，前端原样展示命令与 sha256；
  用户点「确认执行并安装」后才带 `acceptCommandSha256` 重试。代码中没有 `-y` / `--yes`。
- 插件可能携带钩子与 MCP/LSP 服务；详情页明确提示「启用前请确认来源可信」。

## 5. 技能联动

- `discoverSkillsForProject` 在本地/WSL 扫描后调用 `filterDisabledPluginScans`，把落在已禁用
  插件安装路径下的技能剔除。判定用安装路径前缀，大小写按平台归一；前缀相同的兄弟目录不会误伤。
- WSL 侧 CLI 报出的是发行版内路径（`/home/...`），本地技能扫描读的是 UNC；过滤前先
  `wslToUncPath` 换算，否则禁用永远匹配不上。
- 判断"这条安装属于当前项目"时，项目路径同时按 UNC 与发行版内路径两种形态比较：走 Milevia
  安装到 WSL 项目时 CLI 记录的是 `/home/...`，只比 UNC 会把本项目自己的 project/local 记录
  当成别的项目跳过，被禁用插件的技能仍会显示为可用。
- 其他项目的 project/local 安装不会拿来当本项目的禁用根，技能树不受无关项目影响。
- SSH 远端的 find+cat 结果同样按远端 CLI 报出的 `installPath` 过滤（`parseRemoteSkillOutputExcept`），
  禁用插件的技能不会继续显示为可用。
- 插件清单读取失败时返回空过滤集：读不到不等于没有，不能因此改变技能可用性。
- 对话页「插件」块改为显示 `已启用 / 已禁用 / 状态未知`，并提供「管理插件」跳转到 `/plugins`。
- 项目插件接口 `/api/projects/{id}/plugins` 升级为：支持插件子命令的 CLI 走 CLI 清单（远端也
  可以），其余工具退回磁盘扫描并标注「状态未知」。

## 6. 缓存与并发

- 列表按 `runner + agent + 项目路径 + available + 是否带市场` 缓存 30 秒；任何写操作立即失效。
  技能过滤只需要启用状态，读的是不带市场的轻量 key，不会为了一次技能扫描多跑市场子命令。
- 写操作后 `pluginCacheEpoch` 递增：写前发起、写后才返回的列表查询不会把旧清单回填缓存。
- 同一 key 的并发读取合并成一次执行（技能过滤与插件列表经常同时冷启动）。
- 能力位缓存 10 分钟；CLI 版本不变时能力不会变。
- 版本升级后 CLI 子命令变化，最迟 10 分钟后自动重探。
- 详情、启停、升级、卸载与项目插件面板只需要记录本身，走不带市场清单的查询，不额外调用
  `marketplace list`。

## 8. 已知限制

- Codex 没有 enable/disable/update 子命令，页面只显示市场、安装与卸载；范围固定为 user。
- 远端 SSH 的只读兜底扫描不可用；但如果该 CLI 支持插件子命令，远端清单可以正常读取。
  远端的组件数量与清单内容依赖 CLI 输出，不在本机磁盘上调 `enrichPluginRecord`。
- 组件数量优先取 CLI 输出；CLI 不提供时（Claude 的磁盘路径在远端不可读）可能显示 0。
- 清单文件超过 128KB 直接跳过读取，只保留 CLI 给的名称/版本，避免列表热路径读入异常大文件。
- 插件详情里的 token 开销来自 `claude plugin details` 的文本输出，格式变化时会退化为空。
- 同一个插件同范围重复安装（CLI 自身允许）时仍按第一条记录处理；界面不提供"同范围多副本"的
  操作语义，用户应在 CLI 侧清理。
- Claude/Qoder 的 `marketplace remove` 省略 `--scope` 时会删除所有范围里的同名声明；界面在
  确认框里明确写出这一点。Codex 的市场只有全局配置，不存在范围选择。
- cursor / codebuddy / opencode 走磁盘兜底扫描：项目根下的插件标为 project，启用状态一律
  "未知"；清单文件里的 `enabled/stateKnown/managed/scope` 不会被采信，状态只能来自 CLI。
