# 定时任务使用与实现说明

> 日期：2026-08-20<br>
> 状态：已实施<br>
> 关联：[任务编排与人工下发](07-任务编排与人工下发.md)、[对话页 Skill 区域实现方案](22-对话页Skill区域实现方案.md)、[项目级 AI 配置重塑方案](21-会话页项目级AI配置重塑方案.md)

## 1. 定位与范围

定时任务用于在指定时间自动向项目中的 Claude Code 或 Codex 发起一次独立执行，适合例行检查、日报、依赖巡检和维护工作。

它与“任务看板”是两个独立模型：

- 任务看板管理需要人工下发、验收和跟踪的开发计划；
- 定时任务按日历规则自动运行，不进入看板的人工验收生命周期；
- 每次定时执行会创建独立会话和运行记录，既不会复用当前对话，也不会把上下文带到下一次执行。

当前支持的计划类型如下：

| 类型 | 配置 | 示例 |
| --- | --- | --- |
| 单次 | 日期、时间与 IANA 时区 | `2026-08-21 09:30`，`Asia/Shanghai` |
| 每日 | 每天的时分与 IANA 时区 | 每天 `09:00`，`Asia/Shanghai` |
| 每周 | 星期、时分与 IANA 时区 | 每周一、周五 `18:00`，`Asia/Shanghai` |

不支持 Cron 表达式、事件触发、跨项目任务、自动重试、自动验收或在系统级后台常驻执行。

## 2. 运行前提与时间语义

定时任务的调度器绑定 Milevia control-server 的生命周期。桌面应用关闭、网页开发服务停止或 control-server 退出后，调度立即停止。

- 调度器按 10 秒间隔检查到期任务，不提供精确到秒的开始保证；项目工作区繁忙时还会继续等待。
- Milevia 未运行期间到期的任务**不会补跑**。恢复启动时，重复任务会计算下一个未来执行时间；错过的单次任务会自动停用。
- 如果 Milevia 在一次运行已开始后退出，该次运行会在下次启动时标记为“已中断”，不会自动续跑或重试。
- 单次任务必须至少设置在当前时间 10 秒之后；已过期的单次任务不能恢复，需编辑为未来时间后再启用。
- 所有计划使用 IANA 时区名，例如 `Asia/Shanghai`、`America/New_York`、`UTC`。单次任务的日期时间按所选时区解释，而不是浏览器或服务器时区。
- 夏令时切换中不存在的本地时刻会跳过当日，避免在错误的墙上时间执行；不会以替代时刻补跑。

因此，定时任务适合“应用保持运行期间的例行自动化”，不适合作为要求 24 小时可靠触发或必须补偿的服务器级调度系统。

## 3. 使用指南

### 3.1 新建任务

1. 打开目标项目，进入“任务 → 定时任务”。
2. 点击“新建定时任务”。
3. 填写名称和提示词，选择 Agent 与权限。
4. 选择单次、每天或每周，并设置时间、时区；每周任务至少选择一个星期。
5. 按需勾选可调用的 Skill，确认“保存后立即启用”状态后保存。

名称仅用于列表、通知和历史会话标题；提示词才是发送给 Agent 的工作内容。提示词应清楚说明目标、范围、检查项、输出格式和是否允许修改文件。例如：

```text
检查当前分支的未提交变更和测试状态。
不要修改任何文件。按“风险、失败项、建议操作”三段输出中文摘要。
```

### 3.2 Agent 与权限

定时任务可以单独设置 Agent 和权限，不继承当前会话的临时选择。可用组合由服务端校验：

| Agent | 可选权限 | 适用场景 |
| --- | --- | --- |
| Claude Code | 需审批、完全控制 | 希望保留审批，或允许完整自动执行 |
| Codex | 只读分析、项目内执行、完全控制 | 巡检、受限修改或完整自动执行 |

“完全控制”会允许 Agent 直接执行其运行环境中的操作。应仅用于已经审查过提示词、项目路径和 Skill 指令的任务；例行检查优先使用只读或需审批模式。

### 3.3 运行与管理

列表展示下次运行时间、最近状态、Agent、权限和已选 Skill 数量。可执行以下操作：

| 操作 | 行为 |
| --- | --- |
| 立即运行 | 立刻创建一次执行，不改变原来的日历计划；暂停的任务也可以手动运行。 |
| 暂停 | 清空下次执行时间，并停止尚未取得 Run 的排队实例；已开始的运行会继续。 |
| 恢复 | 为重复任务从当前时间重新计算下次执行；过期单次任务必须先改为未来时间。 |
| 编辑 | 修改后只影响未来新建的运行；已经排队或已完成的运行继续使用原有快照。 |
| 删除 | 有排队或运行中实例时不能删除；删除后会移除该任务及其运行记录。已产生的独立会话仍可作为只读历史查看。 |

每个任务详情最多显示最近 100 条运行记录，状态含义如下：

| 状态 | 含义 |
| --- | --- |
| 等待执行 | 已到期或手动触发，但正在等待项目工作区可用。 |
| 执行中 | 已创建独立会话并启动 Agent。 |
| 已完成 | Agent 运行正常结束。 |
| 需处理 | 无法创建会话、Skill 不再可用、Agent 失败等错误；详情会显示失败原因。 |
| 已停止 | 在启动前被暂停或编辑为停用。 |
| 已中断 | Milevia 在该次运行启动前或运行中关闭。 |

## 4. Skill 调用

编辑器会根据所选 Agent 和项目实际运行环境读取可用 Skill，勾选后才允许保存。保存和真正启动前都会再次校验，避免引用已删除、切换 Agent 后不适用或远端不可访问的 Skill。

Skill 的来源与发现规则如下：

| Agent | 用户级 | 项目级 | 插件来源 |
| --- | --- | --- | --- |
| Claude Code | `~/.claude/skills` | `<project>/.claude/skills` | `~/.claude/plugins/**/skills` |
| Codex | `~/.codex/skills` | `<project>/.codex/skills` | 无 |

- Windows 项目读取 Windows 环境；SSH 项目读取远端环境；WSL 项目当前只读取项目级 `.claude/skills` 与 `.codex/skills`，不会扫描 WSL 用户目录。
- 同名 Skill 优先使用项目级定义；Skill 信息来自其 `SKILL.md`。
- 运行时会在用户提示词前加入选中的 Skill 名称，并要求 Agent 遵循每个 `SKILL.md` 的指令。Skill 名称及提示词会一并固化到本次运行快照。
- Skill 不是隔离或权限边界。其指令与当前任务选择的 Agent、权限模式共同生效，必须按实际影响评估。

## 5. 执行模型与并发规则

```text
到达计划时间 / 点击立即运行
  -> 固化名称、提示词、Skill、Agent、权限和配置档案修订
  -> 创建独立的 Scheduled 会话
  -> 申请项目工作区
  -> 启动既有 Run、实时事件和通知链路
  -> 记录成功、失败、停止或中断结果
```

每次运行保存不可变快照，包括名称、提示词、Skill、Agent、权限和 Agent 配置档案修订。之后即使编辑任务、切换默认配置或修改 Skill，已排队和历史运行仍按自己的快照解释。

并发限制：

- 同一个定时任务最多只能有一个“等待执行”或“执行中”实例；再次点击“立即运行”会被拒绝，直到该实例结束。
- 定时任务与项目中的普通会话、任务下发共用工作区互斥锁，避免同时修改同一项目目录。
- 工作区被占用时，定时实例保持“等待执行”，调度器会在后续检查中重试；不会因为等待而丢弃本次实例。
- 每次执行的会话标题以 `Scheduled: <任务名称>` 开头，且为只读，不能在该会话中继续发送消息。
- 完成、失败和停止会进入现有通知中心；中断状态会保留在运行历史中。

## 6. 数据与 API 边界

数据保存在 control-server 的 SQLite 数据库中。`scheduled_tasks` 保存当前配置，`scheduled_task_runs` 保存每次执行的历史与快照；数据库迁移会自动创建表和补齐后续新增的快照列。

前端通过下列 REST API 访问，所有接口都沿用现有项目和会话的访问控制：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `GET` | `/api/projects/{projectID}/scheduled-tasks` | 列出项目的定时任务及最近运行。 |
| `POST` | `/api/projects/{projectID}/scheduled-tasks` | 创建定时任务。 |
| `GET` | `/api/scheduled-tasks/{scheduledTaskID}` | 查询任务详情和最近 100 条运行记录。 |
| `PATCH` | `/api/scheduled-tasks/{scheduledTaskID}` | 更新任务配置。 |
| `DELETE` | `/api/scheduled-tasks/{scheduledTaskID}` | 删除无活动实例的任务。 |
| `POST` | `/api/scheduled-tasks/{scheduledTaskID}/pause` | 暂停任务。 |
| `POST` | `/api/scheduled-tasks/{scheduledTaskID}/resume` | 恢复任务。 |
| `POST` | `/api/scheduled-tasks/{scheduledTaskID}/run` | 立即运行一次。 |
| `GET` | `/api/scheduled-tasks/{scheduledTaskID}/runs` | 查询最近 100 条运行记录。 |

创建和更新请求使用的主要字段为 `title`、`prompt`、`skills`、`agentId`、`permissionMode`、`scheduleType`、`timezone`、`runAt`、`timeOfDay`、`weekdays`、`enabled`。其中 `scheduleType` 只能是 `once`、`daily` 或 `weekly`；`weekdays` 使用 `1` 至 `7` 表示周一至周日。

## 7. 排查与维护

| 现象 | 检查方式 |
| --- | --- |
| 到点未执行 | 确认 Milevia/control-server 持续运行、任务已启用、时区为有效 IANA 名称，并查看下次运行时间。 |
| 任务一直等待 | 查看项目中是否有普通会话、任务或其他定时实例占用工作区；其结束后会自动重试。 |
| 保存或启动提示 Skill 不可用 | 确认所选 Agent 对应环境中的 `SKILL.md` 仍存在；切换 Agent 后重新选择 Skill。 |
| 单次任务无法恢复 | 将日期时间改为至少 10 秒后的未来时间并保存，再启用。 |
| 运行显示中断 | 表示 Milevia 在该次执行前或执行过程中关闭；根据需要手动立即运行或等待下一次重复计划。 |

功能回归验证至少覆盖：

```bash
cd apps/control-server
go test ./... -count=1
go test -race ./... -count=1
go vet ./...

cd ../..
pnpm --filter @milevia/web test
pnpm --filter @milevia/web build
```

重点测试项包括：时区与夏令时计算、错过计划不补跑、Skill 校验、运行快照、工作区等待、暂停/停用排队实例、删除后的只读历史会话，以及前端在切换任务时重置编辑表单。
