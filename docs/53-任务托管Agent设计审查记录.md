2026-11-03 实施核对：首期实际开放 Windows 本机 Claude Code，Codex 与其他平台未开放；多个未启动草稿不占目录，一个项目只能启动一个未结束会话。存储、输出截断和进程容器的实际限制已同步至方案 §18 与实施记录 §17 起。本轮另补齐独立角色配置、可调逻辑存储预算、事务增长门禁、浏览器产物预占和磁盘余量检查，实际语义见方案 §14.3 与实施记录续记；共享 SQLite 物理配额仍未承诺。下文保留设计阶段的历史推演。

## 1. 审查方法与结论

本次按三个视角复查，并直接修改设计文档：

1. **需求一致性**：逐项对应已确认的用户需求，检查有没有重新要求用户填写目标、执行范围或验收条件，有没有把独立任务强行串联，以及是否独立建设页面。
2. **代码兼容性**：核对任务派发、自动验收、旧编排归属、执行意图与验证表、工作区租约、CLI 档案、只读调用和 checkpoint 实现。
3. **失败场景**：推演任务返工、后续改动破坏先前成果、旧决策迟到、预算到点、重启中断、目录外部修改和人工接管。

首轮修订了 D1—D24；第二轮继续按活性、资源交接、崩溃窗口和最终验收推演，新增并修订 D25—D42；第三轮检查这些规则组合后的行为，修订 D43—D50，补齐复杂依赖、启动竞态、要求版本及部分收口规则。前轮未发现的问题不能据此视为不存在。当前已为这些具体问题补充规则与验收场景，但文档自审不构成“方案绝对无缺陷”的证明。实现前仍需拆分数据库迁移、准入服务和状态机工作；真实 CLI 的权限、进程收敛和浏览器验证能力必须通过实测。

| D23 | 用户没有预写验收标准时，Agent 可能在失败后自行降低标准 | §10：计划版本化，削弱条件说明对应关系并经独立审查；与用户明确要求冲突时必须询问。 |
| D24 | 没有浏览器、基线比较证据或完整输出时，容易把“没验证”写成“已通过” | §10、§14、§16：缺失与失败分开，关键缺证据阻止完成，截断与产物清理明确标记。 |

## 4. 本次明确的设计默认

以下是为形成可实施文档作出的方案取舍，并非用户逐项指定的参数。后续产品审阅可以调整，但调整时应同步修改关联状态、预算和验收场景。

- 首期本机 Runner、一个项目一个未结束托管会话、当前项目目录串行执行。目录中已有改动纳入基线，暂不自动隔离 worktree 或合并成果。
- 每项任务独立上下文，调度和审查首期适配通过能力校验的 Claude Code、Codex；其他实施角色按能力准入。
- 初始任务状态限 todo/action_required，运行中根任务集合固定；内部修复、测试和审查工作项可以自动增加。
- 预算建议默认 4 小时、每任务 3 次额外修复、瞬时故障 2 次重试、全部模型角色合计 200 次调用；单次默认不超过 30 分钟及剩余总时长。
- “调用”按平台 Agent 回合计数，不承诺限制 CLI 内部的每次 API 请求。默认在同一总预算中预留 20% 时间与回合用于最终验收。
- 源文件留存与产物建议每会话合计上限 2 GiB，单条命令完整输出上限 64 MiB；超过限制如实暂停，不丢弃关键证据来伪装成功。
- 暂停继续占用任务和托管目录；需要手动写入时先人工接管。停止后通过新会话继续未完成任务。
- 正式完成在最终验收事务收口，期间页面展示候选通过进度。后续需要即时逐项完成时，必须同时设计成果隔离及验证失效传播，不能只改 UI 文案。

## 5. 实现时仍需验证的边界

这些是已写入验收要求的工程风险，不属于已确认实现能力：

- 当前 AI 并发准入与 Git 索引路径接入托管排他保护，不能遗漏终端、定时任务、回退和开发服务。
- 各 CLI 在实际版本上的权限、输出结构和取消行为，尤其原生后台任务与后裔进程是否真正收敛。
- 外部编辑器无法被平台锁绝对冻结，内容指纹的覆盖和采集时点需要实际验证；报告只证明当时的被验收版本。
- 无 Git、被忽略必要源文件、大文件、不可读文件、路径别名和目录重叠情况下的快照与准入行为。
- 浏览器、测试数据库和外部服务的可用性。关键行为未验证时不能用模型判断替代证据。
- 长过程事件与产物的存储量、脱敏、分页和清理，不能牺牲活动验收和恢复所需记录。

## 25. 真实Linux验收与控制端授权复查（2026-11-04）

Linux本机Claude Code真实四任务及双任务失败隔离均已通过；Windows三种CLI混合双任务也通过，实际Run与不可变规格共同核对角色CLI。Linux浏览器首轮遇到运行环境缺失，人工补齐后正式worker检测环境变化，由Agent自动重验并完成；这证明该场景的恢复路径，不能宣称依赖安装同样由Agent完成。Linux Codex实际模型连接拒绝，有限重试后需要处理，两轮均不记为通过。

## 26. 恢复、模型配置与完成回执复查（2026-11-05）

发现并修复：暂停后的源码核对缺少独立只读授权；Qoder/Cursor 隔离配置丢失原默认模型；验证完成缺少幂等消费，重复回执可能重复插入证据。现在恢复只允许暂停、静默、仍受保护的目标只读采集，模型配置做白名单投影和摘要绑定，验证结果绑定原执行及输入摘要，首次消费要求静默，重复保留原历史。

## 27. 目标最终业务交接复查（2026-11-05）

最终目标交接原来只有目标端 sealed journal，业务 Task.done 仍走本机路径。先加阻断，继而增加控制端持久 intent、事务外目标封存、完整业务绑定复验，以及同事务完成子集、原回执和 releasing。目标释放确认继续独立处理。worker 在普通源码读取前消费未完成交接，避免 sealed 状态拒绝普通读取后陷入循环。

复查补充了四个容易遗漏的分支：封存回复丢失不另建意图；证据正文改变也要使绑定失效；意图落库但尚未送达时不要求远端存在旧 journal；断线在无活动执行时同样会撤销目标授权，需要只读恢复而非复用控制端旧 ACK。更高授权只清除绑定的旧意图，不释放目录或重放旧模型。预算耗尽必须进入明确暂停，不能永久停留在“最终验收”并重复报授权错误。

协议 TargetTime 是请求处理前的时钟样本，不能拿它当成本次封存时间上界；最终时间核对改用已冻结目标授权期限。专项覆盖上述分支并通过竞争检测。当前仍不能据此开放公共跨端准入；普通写入口共享物理目标保护及完整组合验收必须继续实施。
