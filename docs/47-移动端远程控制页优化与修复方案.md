# 移动端远程控制页优化与修复方案

> 日期：2026-10-19
>
> 状态：阶段 A、B 已完成；阶段 C 已完成快照加载器、实例列表与 SSE 生命周期接线，待发消息、正式实时消息、流式消息和运行通知与快照的归并已分别抽为纯函数。实例切换后立即加载新快照的回归已修复并由页面门禁覆盖。阶段 D 已完成原生扫码资源生命周期拆分，移动端配对提交已抽为 `useMobilePairingClaim`，待确认凭据和确认轮询已抽为 `useMobilePairingConfirmation`，桌面端配对会话、生成、确认与轮询已抽为 `useDesktopPairing`。设备状态的完整所有权收口、完整同步 Hook、完整配对 Hook 与阶段 E 至 F 待实施。
>
> 范围：`apps/web/src/pages/MobileRemotePage.tsx`、其新增 Hook/纯函数模块，以及对应测试；不涉及服务端协议变更。

## 1. 目标

在不改变手机端远程控制既有功能、接口和交互语义的前提下，解决两个问题：

1. 页面级源码正则测试会因注释或局部排版变化而失败，不能可靠地作为回归门禁。
2. 实例同步、SSE、会话、配对、任务、文件和 Git 都集中在一个组件中，后续需求很容易引入跨域状态回归。

本方案的完成标准不是把文件机械拆小，而是让每个状态域有明确所有者，并让关键行为能通过执行代码的测试验证。

## 2. 已核实现状

`MobileRemotePage.tsx` 当前约 4,759 行，承担以下职责：

| 域 | 现有入口 | 主要状态或副作用 |
| --- | --- | --- |
| 远程同步 | `loadInstances`、`loadSnapshot`、`applyRealtimeEvent` | 实例切换、快照版本、SSE、轮询、缓存和前后台补偿 |
| 会话 | 会话目录、历史分页、消息发送、停止和草稿 | 乐观消息、流式消息、通知、页面内返回 |
| 配对与设备 | 扫码、配对码、设备别名、解绑、桌面端绑定状态 | 原生扫描插件、权限、定时轮询、本地设备存储 |
| 项目工具 | 任务、文件、Git、优化面板 | 乐观任务、RPC、导航守卫、多个全屏子态 |
| 页面协调 | `goBack`、原生返回键、焦点和浮层 | 子态优先级、关闭顺序、原生/Web 差异 |

远程同步已具备必要的保护：请求代次、SSE 断线重连、快照兜底轮询、可见性暂停和实时消息与快照合并。这些行为必须保留，不能以“简化代码”为理由删除。

当前 `pnpm test` 失败于 `mobile-remote-agent.test.mjs`：该测试读取页面源码并用正则限制 `goBack` 中注释到逻辑之间的字符数。实际返回逻辑仍符合预期，测试却因注释长度变化失败。

## 3. 边界与约束

### 必须保持

- 云端 API、SSE 协议、远程 RPC 的请求形状不变。
- 实例切换时，晚返回的旧请求不能覆盖新实例数据。
- 实时消息先到、快照后到时，消息不能丢失或回退。
- 页面不可见时停止普通轮询；恢复可见后补一次快照。
- 原生返回键与页面返回按钮在共有的文件、Git 和会话退出层遵循同一规则；只由原生返回键处理的任务、菜单、确认框等顶层浮层维持现有优先级。
- 文件与 Git 继续作为会话视图的子态，不改变 URL 或额外引入历史层。
- 既有的乐观任务、消息发送和停止会话行为不变。

### 本轮不做

- 不改云端、控制服务或数据库协议。
- 不引入新的状态管理库。
- 不调整移动端视觉设计或重做页面信息架构。
- 不把所有 JSX 都拆成展示组件；只在状态边界稳定后移动对应视图。

## 4. 实施顺序

### 阶段 A：先修复测试门禁（已完成）

目的：让测试验证行为，而不是验证注释、空行或局部书写方式。

1. 先抽出无 React 依赖的返回策略函数。它只根据页面状态返回抽象意图，例如 `close-overlay`、`delegate-files-back`、`delegate-git-back`、`leave-conversation`；它不能直接调用 `showTree()` 或 `showTopLevel()`。
2. 页面层保留一个执行器：收到 `delegate-files-back` 后才调用 `filesPanelRef.current?.showTree()`，无法再退一层时关闭文件面板；Git 同理。这样面板的内部状态仍由面板拥有。
3. 为策略函数新增独立单元测试，完整枚举原生返回键的优先级：优化面板、任务面板、消息操作行、历史弹层、配对页、文件、Git、会话退出。另为页面返回按钮覆盖其实际可触达的文件、Git、会话退出分支，不能假设两条入口完全相同。
4. 将当前失败的“注释长度”断言替换为上述行为用例。其余源码结构断言不批量删除，只在对应逻辑已有可执行测试后逐条移除。
5. 在仓库根目录运行 `pnpm --dir apps/web test`，修复当前失败项后再进入下一阶段。

验收：修改注释、格式化或重命名局部变量不会导致行为测试失败；真实改变返回优先级时测试会失败。

### 阶段 B：先固定设备与认证状态的所有权（已完成）

新增 `useRemoteDevices`，只负责本地设备记录和活动访问令牌：

- 读取、归一化、更新和删除 `mobile-devices` 中的设备记录。
- 选择活动设备，并向页面暴露只读的 `activeToken`、`activeDevice` 与设备列表。
- 设备别名等纯本地操作。

它不请求云端实例、不读取快照，也不管理配对流程。页面在本阶段继续持有实例和快照；这样下一阶段的同步 Hook 只接收设备域明确提供的活动令牌和设备代次，不会和设备域争夺令牌或当前设备的状态所有权。

`activeToken` 不是单纯的 React 状态。现有 `cloud()` 在未传入特定设备令牌时从本地存储读取认证令牌，因此 `useRemoteDevices.activate(token)` 必须是唯一的激活入口，并按固定顺序同步完成：先调用 `setActiveToken(token)` 写入当前键及兼容旧键，再刷新设备列表和 React 的 `activeToken` 信号。配对成功、切换设备、解绑后顺移、401 失效后的顺移都只能通过这个入口或等价的内部原子动作；不得只调用 React 的 setter。

激活动作还必须递增只读的设备代次（或提供等价的 `deviceEpoch`）。后续同步域以它作为重置键，用来使正在进行的旧设备请求和流连接失效；令牌字符串相同但经历了重新配对或恢复流程时，也不能复用旧代次。

验收：切换、删除和恢复活动设备后，`activeToken` 与本地存储一致；下一次默认云端请求使用新令牌，且没有云端请求时设备入口仍可用。

### 阶段 C：抽离远程同步 Hook

新增 `useMobileRemoteSync`，只负责远程数据的读取和合并：

- 只在 `mobileApp` 分支启用；桌面端的 `agentStatus`、`bindings` 和本地 `api` 调用继续由桌面端域持有。
- 输入为 `activeToken`、`deviceEpoch` 和可见性；输出实例列表、当前实例、快照与切换实例动作。
- `loadInstances`、`loadSnapshot`、请求代次与取消逻辑。
- SSE 生命周期、断线退避、事件解析、快照兜底轮询。
- 实时消息和流式消息与快照合并。
- 前后台可见性补偿。

本 Hook 接收 `documentVisible`，并以回调形式上报已经解析的实时事件；它不直接调用本地通知插件，也不处理通知点击后的导航。页面继续保留通知桥接，或后续单独抽成 `useMobileNotifications`。这样同步层只负责数据一致性，不耦合 Capacitor 权限和 UI 跳转。

页面仅消费该 Hook 暴露的稳定状态与动作，不能继续直接读写其内部 ref。Hook 的返回值应以领域对象组织，例如 `instanceState`、`snapshotState`、`refreshSnapshot`、`switchInstance`，避免重新暴露几十个分散状态。

实现方式：先将请求代次、事件归并、快照归并和重连退避提取为可注入时钟、请求函数和事件流的纯控制器；Hook 只负责把控制器接入 React 生命周期。项目当前使用 `node:test`，不新增测试框架。

认证语义在本次拆分中保持不变：默认请求仍由现有 `cloud()` 从本地存储取得活动令牌，`activeToken` 和 `deviceEpoch` 只用于触发同步域重置，不能形成第二个认证来源。若后续改为让请求适配器显式接收令牌，必须作为单独的行为变更，并为每个请求和 SSE 握手补齐令牌一致性测试。

控制器的实例列表、快照、SSE 事件、重连定时器和错误回调都必须绑定创建时的设备代次及实例标识。切换设备或实例、Hook 清理、令牌失效后，先使旧代次失效，再中止请求和流；任何旧代次的完成回调都不得写入状态、发出通知或安排下一次重连。现有的请求代次只解决同一运行域内的先后请求，拆分后不能假定它能自动覆盖 Hook 重建产生的旧闭包。

验收：

- 保留现有快照和 SSE 相关用例。
- 增加可执行测试：旧实例响应晚到、SSE 消息先于快照、SSE 静默断开、页面隐藏再恢复。
- 增加跨设备测试：切换后 `/v1/instances` 与 SSE 握手使用新令牌；旧设备的实例响应、快照响应、SSE 事件和重连计时器均不能覆盖或污染新设备状态。
- 抽离前后以同一组模拟事件得到相同快照与消息结果。

### 阶段 D：拆开设备配对与原生扫描

新增 `useRemotePairing`，负责：

- 配对码、二维码、过期倒计时和云端确认轮询。
- 调用阶段 B 暴露的设备动作，在配对成功、解绑或切换后更新活动设备。

另新增 `useBarcodeScanner`，只负责原生与 Web 扫码的启动、停止、权限、手电筒、事件监听和卸载清理。它不拥有配对业务状态，只通过 `onScan(value)` 把扫描结果交还给配对 Hook。

配对页同时服务手机端和桌面端，命名不能限定为 `Mobile`；桌面端本地 API 与手机端云端 API 的差异通过两个明确的适配器注入，分别对应既有 `api` 与 `cloud` 调用，不能用一个无类型的通用请求函数抹平错误语义。扫描浮层的 DOM 可见性仍由页面渲染，但插件生命周期只能由 `useBarcodeScanner` 管理。

验收：取消、权限拒绝、扫码成功、无验证码扫码、解绑和切换设备均有独立测试；卸载时扫描监听和相机一定被关闭。

### 阶段 E：分别收敛会话和任务操作

页面协调层持续拥有 `selectedProject`、`selectedConversation`、`mobileView` 和 `sessionSub`，因为它们决定跨域导航。`useMobileConversation` 接收选中的项目、会话、同步快照和 RPC 适配器，负责会话数据派生、历史分页、草稿、消息发送和停止会话；它不能自行改写项目选择或页面视图。

文件和 Git RPC 适配器继续复用既有模块，只保留在会话域的调用入口。

新增 `useMobileTasks` 管理任务筛选、编辑、命令状态、乐观更新和回滚。它接收当前项目、当前会话标识和同步 Hook 提供的命令传输能力，不直接访问全页状态。任务的纯合并与回滚规则继续放在 `lib/task-mutations.ts`，两个 Hook 都不复制判定逻辑。

验收：

- 发送消息不等待桌面端执行完成。
- 停止会话、任务下发、任务创建和失败回滚的现有行为不变。
- 历史分页不会重复请求同一游标。

### 阶段 F：最后拆视图与页面协调

在上述 Hook 稳定后，再提取以下视图组件：

- `MobileProjectList`
- `MobileConversationView`
- `MobilePairingFlow`
- `DesktopRemotePanel`

阶段 A 创建的返回策略函数是唯一规则来源。此阶段若需要 Hook，只能创建薄的 `useMobileBackNavigation` 适配层，把页面状态交给该策略函数并执行其意图；不得重新实现第二份关闭优先级。该 Hook 接收各子态的最小接口，不直接引用同步和配对的内部实现。

验收：页面根组件只负责组合 Hook、决定当前视图和传递动作；返回规则只保留一份可执行判定。

## 5. 每阶段完成后的检查

每完成一个阶段，只执行与该阶段相关的测试，再执行：

```powershell
pnpm --dir apps/web test
pnpm --dir apps/web build
```

阶段 C 完成后，额外检查移动端在以下场景中没有重复请求或状态倒退：切换实例、切到后台再回来、SSE 断线重连、连续收到流式消息。

## 6. 回退策略

每个阶段独立完成并验证，不与后续阶段合并。若抽离后的行为不一致，直接回退该阶段的 Hook 接线，保留前一阶段已通过的测试修复。不得在同步行为出现差异时继续推进视图拆分。
