# 44 本地启动桌面端与移动端

面向"改完代码要在真机/真外壳里看一眼"的场景。发布流程不在这里，见 `35-发布操作手册.md`。

## 0. 先选对路线

| 你要验证什么 | 用哪条 | 需要的外壳 |
| --- | --- | --- |
| 纯前端（页面、样式、交互、任务流） | `pnpm dev` → 浏览器 `http://127.0.0.1:5173` | 无（Go 控制服务 + Vite） |
| 桌面端外壳能力：托盘、系统 Toast、在线升级、sidecar 生命周期、WebView2 行为 | `pnpm --filter @milevia/desktop dev` | Rust + Tauri CLI |
| 手机端 App（Capacitor 原生包） | §3 路线 A/B | Android SDK + JDK |
| 手机浏览器里的远程控制页 | §3 路线 C | 无 |

这几条路线共用同一份 `apps/web` 前端代码，差别只在**谁托管它**以及**能拿到哪些原生能力**。

## 1. 前置条件

```bash
node -v      # ≥ 22
pnpm -v      # ≥ 10.17.1
go version   # 控制服务与 sidecar；README 要求带 CGO 的工具链
```

桌面端额外要 Rust（`cargo -V`）与 WebView2 运行时；手机端额外要 `ANDROID_HOME` 指向 SDK 与一个 JDK（本机为 `D:\Android\Sdk` + JDK 21，实测可构建）。`apps/web/android/variables.gradle` 里 `minSdkVersion = 24`、`compileSdkVersion = 36` —— 低于 Android 7.0 的设备/镜像装不上包。

```bash
pnpm install          # 仓库根目录，一次装齐 workspace
```

## 2. 桌面端

```bash
pnpm --filter @milevia/desktop dev
```

这条命令实际做的事（`apps/desktop/scripts/dev.mjs`，按顺序）：

1. 读 `apps/agent/.env.windows` 进环境变量（`MILEVIA_CLOUD_URL` / `MILEVIA_CLOUD_AGENT_TOKEN` / `MILEVIA_INSTANCE_ID`）——**手机端能不能看到这台电脑在线，取决于这一步**；
2. 若上面有 agent token 且当前没有 agent 在跑，用 `apps/agent/start-agent.ps1` 后台拉起 agent；
3. `pnpm run prepare-assets`（图标）；
4. `node scripts/build-sidecar.mjs` → 产出 `apps/desktop/binaries/milevia-{control,approval,agent,terminal-bridge}.exe`（增量，只有源码变了才重编）；
5. `tauri dev` → 由 `tauri.conf.json` 的 `beforeDevCommand` 自己起 Vite（**127.0.0.1:1420**，与 §0 第一条路线的 5173 是两个不同进程）。

调试版从 `apps/desktop/binaries/` 取 sidecar，装机版从安装包资源目录取（`src-tauri/src/main.rs` 里 `#[cfg(debug_assertions)]` 分支）。

### 与装机版的关系（最容易踩）

- 桌面端注册了 `tauri-plugin-single-instance`，dev 版与装机版 **identifier 相同**（`com.milevia.desktop`）→ 同时只会有一个实例。起 dev 前先退出装机版（托盘图标右键退出），否则新起的进程只会把已有窗口唤到前台然后自己退出，看起来像"没反应"。
- dev 版与装机版**共用同一个数据目录** `%LOCALAPPDATA%\com.milevia.desktop`，包括同一个 `EBWebView`（WebView2 profile）和同一个 SQLite 库。在一边改的东西另一边会看到。
- 只想跑前端逻辑时不必碰桌面端：`pnpm dev` 更轻，端口也不同（5173 vs 1420）。
- 桌面端 dev 会自己拉起 sidecar 控制服务（随机端口 + 每次启动新生成的会话令牌，见 README），与 `pnpm dev` 那份 8080 是**两个进程**；一般二选一，不要以为它们连着同一份数据。

### 只想跑控制服务 + 前端

```bash
pnpm dev                                    # 控制服务 8080 + Vite 5173
AUTO_WEB_PORT=5174 AUTO_CONTROL_PORT=8081 pnpm dev   # 端口被占时换一套
AUTO_CLEAR_PORTS=1 pnpm dev                 # 允许脚本 kill 掉占用端口的进程（默认不允许）
```

健康检查：`curl http://127.0.0.1:8080/api/health`。等待超时由 `AUTO_STARTUP_TIMEOUT`（秒，默认 60）控制。

## 3. 移动端

### 3.1 后端地址是怎么定的（先看这段，否则一定连不上）

`apps/web/src/pages/MobileRemotePage.tsx:600-603`：

- **原生包**：`VITE_CLOUD_URL` 在**构建期**被烘进包里；没设就用兜底值 `https://keyanjia.info:8443`。`apps/web/` 下没有 `.env` 时就是这个默认值 —— 也就是说本地构建的 APK 连的是**线上云端**，不是本机。
- **原生包不能指向 `http://` 局域网地址**：`capacitor.config.ts` 设了 `androidScheme: "https"`，https 页面里发 http 请求会被 WebView 当混合内容拦掉。
- **Vite 开发模式**：`cloudURL` 取空串，云端请求走相对路径 `/v1`，由 `apps/web/vite.config.ts` 的 proxy 转发到 `VITE_CLOUD_URL`（未设置时该代理不存在，只有 `/api`、`/ws` 指向本机控制服务）。
- 顺带一个实测观察：原生包启动时 logcat 里会出现 `Handling local request: https://localhost/api/agents` —— 相对路径 `/api/*` 在原生包里落到 WebView 自己的源上（`androidScheme: https` → `https://localhost`），由 Capacitor 当成本地静态资源处理。也就是说 APK 里凡是走 `api()` 的共享组件都拿不到控制服务的数据，只有 `cloud()` 那条路通；排查"App 里某块内容空白"时先想到这条。

### 3.2 路线 A：装到模拟器（本机已验证）

```bash
# ① 建/选 AVD（本机现成有两个）
/d/Android/Sdk/emulator/emulator.exe -list-avds
#   Milevia_API30 / Milevia_Pixel6_API35

# ② 起模拟器（后台，开机约 30–60s）
/d/Android/Sdk/emulator/emulator.exe -avd Milevia_Pixel6_API35 -no-snapshot-save -gpu host

# ③ 出包并装机（仓库根目录）
cd apps/web && pnpm build && pnpm exec cap sync android
cd android && ./gradlew assembleDebug --console=plain -q
/d/Android/Sdk/platform-tools/adb.exe install -r app/build/outputs/apk/debug/app-debug.apk
/d/Android/Sdk/platform-tools/adb.exe shell am start -n info.keyanjia.milevia/.MainActivity
```

要点：

- **顺序不能反**：`cap sync` 把 `apps/web/dist` 拷进 `android/app/src/main/assets/public`，若在 `gradlew` 之后才 sync，打出来的包带的就是旧前端。
- `adb` 通常不在 PATH，用 `$ANDROID_HOME/platform-tools/adb.exe` 全路径。
- 包名 `info.keyanjia.milevia`（`capacitor.config.ts` 的 `appId`），入口 Activity `.MainActivity`。
- 版本号 `versionName 0.1.8` / `versionCode 6` 由手机端发版脚本维护（`apps/web/android/app/build.gradle:37-38`），本地构建不会自动递增。
- 装不上（`INSTALL_FAILED_UPDATE_INCOMPATIBLE`）＝签名不一致，卸载重装即可；手机端会丢配对状态，需要重新绑定（同 `35-发布操作手册.md` 故障排查那条）。

配对：桌面端「远程访问」生成二维码 + 6 位校验码，手机端扫码或**手动输入校验码**。模拟器摄像头不一定有画面，走手动输入更稳；两条路汇到同一个 claim 接口，且**令牌要等电脑端点「确认绑定」才激活**。

### 3.3 路线 B：真机

```bash
adb devices          # 必须能看到设备；看不到先检查 USB 调试授权
cd apps/web/android && ./gradlew installDebug   # 或上面的 assembleDebug + adb install -r
```

真机要连上原生包里烘进去的那个云端（默认线上 `keyanjia.info:8443`）。想让真机连你本机的控制服务，需要自己给 https 的入口（反代），不在本文范围。

### 3.4 路线 C：手机浏览器（调移动端 UI 最快，不用出包）

```bash
# /v1 的代理只在设了 VITE_CLOUD_URL 时才存在（apps/web/vite.config.ts:6），
# 而 MobileRemotePage 全部请求都打到云端 /v1/*，所以这个变量不能省。
VITE_CLOUD_URL=https://keyanjia.info:8443 AUTO_WEB_HOST=0.0.0.0 pnpm dev
ipconfig | grep -A2 "无线局域网适配器"     # 拿到本机局域网 IP
```

手机与电脑连同一 Wi-Fi，打开 `http://<本机IP>:5173/mobile`。

- 这条路线**仍然走云端和配对流程**（手机端与电脑端 agent 连的是同一个云端），它省掉的只是"构建 APK + 装机"这一步 —— 改一行前端代码刷新就能在手机上看到。
- 前提是电脑端的 agent 在线（§2 第 1–2 步），且云端可达。
- 手机浏览器（Chrome）里 `window.Notification` 在非 https 地址上不存在，设置页的"使用系统通知"两项会自动收起（判定见 `apps/web/src/lib/notifications.ts` 的 `webNotificationsSupported`）；这不影响其余功能。
- 要看手机上的报错：手机插数据线 + 开 USB 调试，在**电脑**的 Chrome 打开 `chrome://inspect` 远程调试那个页面。

## 4. 改完代码怎么最快看到

| 改动位置 | 生效方式 |
| --- | --- |
| `apps/web/src/**`（桌面 dev / 浏览器） | Vite 热更新，无需重启 |
| `apps/web/src/**`（原生包） | `pnpm build && pnpm exec cap sync android && (cd android && ./gradlew assembleDebug)` → `adb install -r` |
| `apps/desktop/src-tauri/**` | `tauri dev` 会增量重编 Rust（首次几分钟） |
| sidecar（`apps/control-server`、`apps/agent` 等） | 重跑 `pnpm --filter @milevia/desktop dev`，它会在第 4 步增量重编 `binaries/` |

## 5. 排查

| 现象 | 先看 |
| --- | --- |
| `Port 5173 is already in use` | 换端口或 `AUTO_CLEAR_PORTS=1`（会 kill 占用进程） |
| 起 dev 桌面端"没窗口" | 装机版还在跑，被 single-instance 顶掉了；先退装机版 |
| 手机端看不到电脑在线 | agent 没起来：检查 `apps/agent/.env.windows` 里有没有 `MILEVIA_CLOUD_AGENT_TOKEN`，以及云端 agent 是否在线 |
| App 里请求全失败 | 原生包连的是烘进包里的云端（§3.1），不是本机；`adb logcat -d \| grep -i capacitor` 看实际打到的地址 |
| 前端改了但 App 里没变 | 漏了 `pnpm build` 或 sync 在 gradle 之后 |
| 要看 WebView 里的报错 | 装机版没有 DevTools；dev/debug 构建默认开着（Tauri 的默认行为），试 `Ctrl+Shift+I` |
