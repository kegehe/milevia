## 3. A1 已实现范围

- 新增 `task_execution_claims` 和追加式归属审计。认领与 TaskRun 启动共用事务；同 owner 重放幂等，不同 owner 冲突，释放必须同时匹配类型和 ID。
- 旧编排入队、状态变化和移出由数据库约束同步长期归属，覆盖批量与单项路径。`stopped` 仍持有归属；真正结束或显式移出后释放。普通派发只在活动 Run 期间认领。
- 迁移在通用 Run 恢复前回填旧编排及活动普通执行。只有唯一且确实属于同任务的旧执行意图才能证明历史来源，其余保留 `legacy`。
- 派发显式传递执行来源，持久化 `execution_source/execution_owner_id`，不再通过非空工作目录判断旧编排。普通派发不能借用旧编排意图，意图不能跨任务关联。
- 事务内保护托管任务的编辑、删除、重新打开、普通验收及依赖关系两端；批量验收跳过托管任务。普通成功回调保存 Run 事实，不直接完成托管任务或释放长期归属。
- Task 查询以批量方式返回当前认领，TaskRun 返回来源；保护后台标题更新、普通任务停止及项目删除入口。

旧编排采用数据库触发器同步认领，是为了在首批覆盖现有全部入队与清理路径；业务派发仍通过公共准入函数。触发器只依赖稳定的认领表，不引用会被旧迁移重建的 `task_runs`。后续托管 start 事务必须同时建立会话、任务认领和目录 pending 准入，不能只调用任务认领函数便开始实施。

## 5. A2 已实现范围

- 新增持久化 `workspace_admissions`，提供 pending → owned → releasing → 释放的准入基础。pending 原子阻止新的重叠目录操作，已有操作继续收敛；普通 AI 之间原有共享规则保持不变。任务认领可以与 pending 准入共用一个事务，失败不留下半认领或内存中的幽灵锁。
- 本机目录按绝对路径、链接解析、Windows 句柄最终路径与目录身份核对，覆盖父子目录、跨项目同目录及大小写别名。尚未创建的工作树按最近真实祖先解析；远端 Runner 使用独立命名空间，首期不能建立远端托管准入。项目路径移动、目录替换和链接改指向不能默默沿用原准入。
- 普通会话、任务派发及定时任务复用消息启动的准入；文件、Git 索引与其余 Git 写操作接入现有租约的托管保护。旧编排的直接 Git 命令、验证、独立审查及工作树创建/恢复/清理增加实际目录保护；会话隔离工作树同时保护源目录与实际创建/删除目录。Git 读取禁用可选索引刷新，避免查看状态顺带写入。
- 终端在 Open 前登记，直到进程等待和输出读取都结束才释放；关闭记录、页面断开或启动失败不被直接当作进程已退出。项目开发服务在真实启动前登记，退出与输出读取结束后释放；启动失败回收占用，重启重新准入。只读分析、冲突建议和命令目录探针同样不能借“只读”名义启动未登记的 CLI；临时流式冲突建议会等 Session 的退出通道关闭后释放目录。
- 普通快照创建、代码恢复和 Codex 原生回退增加目录保护。托管 Run 跳过旧 shadow Git 检查点，后续由专属证据与最终快照管理。角色会话使用独立的 `supervision_conversation_links`，在首个 Run 之前即可登记；`supervision_run_links` 保存会话、工作项、角色、attempt、目录准入和 epoch，并核对项目、实际目录及任务认领。
- 活动角色会话的普通发送、停止、清空、删除、批量删除、回退、交接、权限/模型/推理强度修改、工作区切换及归档受到服务端保护；自动历史裁剪保留角色过程。启动先恢复目录保护、递增 epoch，再处理普通 Run；托管的 launching/running 事实转为 unknown，由后续专属恢复核对，普通中断恢复不改写它们。
- 重启会幂等清理已进入 releasing 且路径与执行均已收敛的残留；任务认领及目录在同一事务中释放，保留归属审计。路径改变、仍有操作、活动 TaskRun 或无法确认退出的关联 Run 均继续保留保护，传输 completed 不能替代进程收敛事实。

内存准入镜像与数据库的固定锁顺序为 SQLite 事务 → admission gate，成功提交后才更新镜像；gate 内不启动或等待进程，也不另取数据库连接。普通操作登记只增加托管保护，不把终端、开发服务或只读分析改成原有普通会话的独占租约。

本批尚未开放托管启动 API 或新页面。后续 B1/B2 必须把 Session、选中任务认领、pending 准入放在同一启动事务，完成托管子令牌、launch/control gate、CLI 角色权限、原生 Session 交接、实际进程/后裔及验证资源核对，再允许自动派发。当前 unknown 是保留保护的恢复状态，不是已经实现自动诊断或恢复运行。

## 7. B1 已实现范围（第一部分）

本批是内部领域服务，尚未注册托管启动 HTTP 路由、启动调度 worker 或调用真实 CLI，也未新增页面。以下能力已落到代码和数据库，不代表完整托管功能已可用。

- 新增 `supervision_sessions/tasks/decisions/work_items/events/outbox`。会话业务版本与事件序号分开；事件和状态在同一事务提交，回滚不产生幽灵事件。数据库限制每项目最多一个活动托管，草稿不占用任务或目录。
- 启动时在同一事务重新读取全部选中任务及依赖快照、整批认领任务、建立目录 pending 准入和会话状态。任务被删除、跨项目或已被占用时整体失败，不静默跳过。保存项目模型路由的非敏感配置引用，不保存 API Key，也不把账号池伪装成已固定账号。当前仅限制调度 CLI 类型，完整角色配置与能力就绪检查尚未接入。
- pending 等待既有操作收敛后才能转 owned。lease 使用 owner、epoch 和过期时间阻止旧调度器派发；过期租约不能越过尚未确认退出的执行事实直接换代。
- 决策、工作项、稳定 `execution_id`、预算预留及 outbox 在同一事务建立。同版本重复唤醒返回原决策；同一决策最多额外两次格式纠正，每次独立记录执行尝试并计费，不能通过新建决策绕过限制。
- launch 与控制共用 admission gate。启动前重新校验会话版本、租约代际、目录身份、预算与收敛事实，queued → launching 时预留转为已消费。尚无 Run 的 launching 窗口仍占用目录、阻止释放；本服务只产生启动握手事实及截止时间，不运行 CLI。
- 后续适配器可登记真实 Run。停止先提交、Run 关联后到时，仍保存真实关联并返回需要取消；用户暂停只阻止后续派发。普通 Run 的 completed 或模型输出不能代替进程退出，必须经可信退出/启动失败回调，并检查关联进程及 Run 收敛后才能结束工作项。
- 调度输出严格限制为单个 JSON 对象、一个动作、正确决策身份/会话/业务版本/事件依据，拒绝重复键、顶层字段大小写别名、未知动作及超过 256 KiB 的输出。同次执行结果不可覆盖，过期或控制后的结果只保留历史。`proposed` 仅表示封套有效，未应用任何业务动作；计划、依赖、证据及动作权限仍需 B2 领域校验。
- 默认预算为活动时长 4 小时、200 个 Agent 回合、单轮最多 30 分钟、最终阶段预留 20%。预留释放只适用于未启动项，启动失败不退款；最终份额不能扩张总预算。预算降低、时间耗尽等停止意图先持久化，再向调用者报告额度不足。活动时长、回合及预留可恢复；修复次数和瞬时重试上限目前仅保存及校验配置，尚未实现对应执行循环。
- pause/stop 先持久化，挂起或取消未启动项，等待实际工作项、Run、目录操作及路径核对全部通过，才进入 paused/stopped。暂停保留任务与目录；停止不代办验收，已实施而未验收的任务进入 `action_required`，未实施任务保留原状态。停止与 releasing 同事务，随后幂等释放目录和任务认领。活动会话不能通过底层 release 绕过停止收敛。
- 服务启动在目录恢复之后、普通 Run 恢复之前处理托管会话。保留暂停/停止意图，递增代际，从工作项账本重建已消费及预留汇总，仅退还未启动项。未知执行保守计算停机时间，标记 unknown 并继续保护；没有执行事实时不计确认无执行的停机时间。此处只恢复保护和事实，不自动续跑。

## 11. B1 Windows 单次调度执行握手

本批继续实现内部单次决策执行链，尚未注册启动 API、启动自动调度 worker 或新增页面。首个严格进程容器实现限 Windows 10 及以上；Linux/Darwin 的严格执行明确返回不可用，不能以原有尽力终止进程组的逻辑冒充同等退出证明。

- 新增 `supervision_executions`：持久化执行 ID、专属 Run、子令牌哈希、命名容器、PID/内核创建时间、实际可执行文件与临时工作目录、执行状态及回执。单次随机子令牌仅留在可信执行器内存，数据库只保存 SHA-256；不能换绑会话、Run、工作项、决策、依据版本或 epoch，不传给模型、前端或普通审批入口。
- launching 后，角色会话、Run、输入消息、长期角色关联、执行账本和凭据额度预留同事务创建。重复准备整体回滚；单次执行器另以 prepared → starting 原子认领，重复唤醒不能通过竞争同一容器误停正在执行的回合。调度会话使用现有消息/事件存储并保持普通消息入口保护，不创建实施 TaskRun，不改变 Task 状态。
- 启动时补齐调度角色的路由快照，包括 CLI 登录和旧 `default_profile_id` 选择。后续执行沿用冻结版本；账号池按该版本选择成员，运行时才解析凭据并事务预留额度。执行前接入档案吊销 gate 和取消登记；执行中续租凭据额度，退出后保存实际用量、校准 TPM、释放额度及收口吊销记录。配置更改不静默替换已选角色凭据。
- Windows 使用 `PROC_THREAD_ATTRIBUTE_JOB_LIST`，在 `CreateProcess` 时原子加入命名作业对象，同时挂起主线程。仅仅 Start 后再 Assign 会留下服务崩溃导致挂起进程未被归组的窗口，因此没有沿用该路径。作业对象设置 KILL_ON_JOB_CLOSE，不允许 breakaway；仅继承明确指定的三个标准流句柄。全局唯一命名避免登录会话命名空间改变造成错误的“不存在”判断。
- 挂起状态先保存真实进程身份，再在 launch/control gate 内复核令牌、版本、lease、目录身份及控制状态并放行线程。pause/stop 先提交时不会运行 CLI；放行先发生时暂停等待当前回合，停止由执行监控取消。放行后的事务失败也保留先前已提交的进程身份，执行器取消进程后重新核对，不丢失事实。
- 严格启动直接调用原生 exe，不执行用户自定义 shell 包装脚本；对当前 npm Claude 固定 shim 只在内容完全匹配已知形状时解析其原生 exe。识别失败明确不可用。CLI 仍在中性临时目录执行，Run 的项目 workspace 表示其托管归属范围；实际 CLI 路径和实际 cwd 另存执行记录，不能把项目范围误称为 CLI 实际读取过的目录。
- 主进程返回后终止并核对整个作业对象、等待标准流收敛，再收口执行、工作项、outbox 与 Run。主进程 Wait、模型 result、普通 Run 终态均不能单独释放保护。容器查询失败、输出未收敛等进入 unknown，保留 Run/任务/目录和额度保护。受保护入口不会使用仅供早期能力实验的 `ProcessWaited` 作为退出证明。
- 单次执行监控每秒核对控制、预算和恢复代际，及时续调度 lease；总预算/实施份额及单轮截止时间由持久事实再次收紧，调用者不能传一个更长 deadline 扩大额度。总预算到期与用户暂停/停止保持各自原因，不误报成普通调度故障。模型建议仅记录为 proposed/invalid/stale，不在此处应用业务动作。
- 专用角色 sink 保存对话、事件及原生 Session ID，复用事件广播和用量采集。持久化失败即取消执行，不能仅记日志继续推进。停止后仍可保存当前回合的真实过程；恢复换代后的旧回调拒绝写入。恢复先将执行账本转 unknown，专用核对只查询命名作业对象，不根据 PID 发信号，避免 PID 复用误伤；确认退出后保留 interrupted/outcome_unknown，不自动解除会话恢复保护、重新派发或补办验收。

作业对象证明的是本执行容器的成员收敛，不能替代浏览器、外部服务、经系统代理启动的进程等独立资源登记。本批调度角色禁用这些执行能力，尚未将该容器协议扩展到实施、测试或审查角色。能力探针仍使用中性目录中的已有探针生命周期；其失败不代表模型已经执行。尚未实现完整恢复解除保护、resume 前代码基线核对或外部验证资源交接。

## 13. B1 内部调度 worker 与控制收口

本批将已有单次调度执行服务接入内部 worker。`startSupervisionWorkerLoop` 启用后扫描持久状态，并消费领域事务提交后的唤醒；当前尚未在 `New` 中默认启动，也未开放 HTTP 启动 API。后续产品入口需完成角色能力、项目基线和动作应用检查后再接通，不能将内部循环可运行等同于完整托管已可使用。

- 唤醒由状态/事件事务成功提交后发出，失败回滚不发送通知。提示使用有界队列；丢失、队满或执行中的重复提示均由每 30 秒的数据库补查兜底，不依赖页面 WebSocket。初次启用也执行补查。
- 每会话最多一个活动处理器，不同项目可独立推进；工作项仍走已有持久 lease、目录身份与 launch/control gate。相同业务版本已有 proposed/applied/stale/cancelled 结果时不再调用模型，不因日志、重复提示或 lease 过期重跑同一有效建议。proposed 仍只保存建议，不应用实施、测试或验收动作。
- 目录 pending 时先等待已有操作收敛再转 owned。恢复中的会话只核对 unknown 容器，继续保留恢复保护；不解除 reconciling/outcome_unknown、不重放旧执行、不自动 resume。停止的 releasing 残留可再次补查释放，但仍要求真实执行和路径核对通过。
- 一次唤醒最多初次决策加两次格式纠正；每轮使用独立 execution_id、输入快照和预算记录。纠正观察显式带上一轮 execution/attempt、无效输出及校验错误，作为不可信资料；不修改首次观察。重复唤醒不能重置次数，预算不足可提前暂停。
- 周期检查消费已有预算与控制服务；真实回合期间仍由单次执行监控每秒响应停止、预算和恢复 fencing，暂停等待已运行回合收敛。回合返回后立即尝试控制收口。停止不会代办验收，暂停继续保留任务和目录。
- 预算补查区分已有 queued 预留与下一轮新增预留，修正最后一轮已预留额度被再次虚加一轮而提前暂停的问题。已有尝试仍按原账本消费，不增加总预算或动用最终预留。
- launching 后创建角色 Run/额度失败时，可信补偿必须核对工作项身份、epoch、没有任何 execution 身份或 Run 关联，才能将未启动事实收口。已消费的尝试不退款；保留 pause/stop 意图，其余进入 needs_input/scheduler_start_failed，不伪造运行成功。已有执行事实、旧代际或外来工作项不能借补偿释放保护。
- 输入哈希异常在单次执行器原子认领后核对，确认尚未启动时收口已准备的 Run，避免卡在 prepared。成功 CLI 返回空候选也记录为 invalid，进入相同的有限纠正流程，不永远停在 running 决策。
- worker 启用与 `Close` 使用同一准入 gate 登记 WaitGroup；关闭先禁止新增处理器、取消运行上下文，再等待执行与领域事实收口后关闭数据库。启用幂等，关闭后不能重新启动。没有把 worker 交给页面或独立的无主后台进程。

## 15. B2 项目上下文与计划动作

本批将项目源码基线、规则来源及动态计划接入内部 worker。目录成为 owned 后先采集启动基线，再准备新决策；采集引起版本变化时取消旧 queued 观察，重新绑定版本。调度回合退出并完成进程核对后，只对 `record_plan` 应用领域事务，其余动作仍保存为 proposed。尚未开放启动 API、默认后台启用或独立页面。

- 基线采集不执行 Git、Shell 或模型。用受目录约束的文件句柄读取项目，比较连续两次完整清单的内容哈希及行为元数据；不以 mtime 证明内容相同。包含未跟踪及 gitignored 源文件，记录目录身份、普通文件、执行权限及链接目标。链接不跟随；二进制保留哈希和缺口，大文件记录超限缺口。`.git`、依赖、构建/缓存目录及已知敏感路径显式排除并保留清单，应用数据目录同样排除，项目自身不能位于应用数据目录内。数据目录规范化失败时直接拒绝采集。
- UTF-8 文本源码按 SHA-256 在 SQLite 内容表去重，清单单独寻址；每次变化保存对应上下文指针。普通文本单文件最多 4 MiB、每次扫描总读取最多 64 MiB、清单最多 10000 项。二进制、敏感内容、超限及未解析链接不能冒充已覆盖输入，计划范围涉及这些项时拒绝。已知密钥/Bearer/private-key 模式命中时不留存正文；这属于有限模式识别，不承诺识别任意格式的秘密。
- 记录祖先、项目及嵌套 `AGENTS.md`、`CLAUDE.md` 的来源、作用域、正文和哈希；规则快照合计上限 256 KiB。规则为目录、链接、超限文件或不可保留正文时直接失败，不能静默略过。首次 baseline 不覆盖，后续源码或规则漂移记录到 current 后进入 `needs_input/workspace_or_rules_drift`，不把新规则自动当作扩权授权。调度观察冻结启动上下文和各任务当前计划，尚未实现模型按需读取源码的有界资料动作。
- 采集前持久登记 collecting，文件 I/O 不持有领域 gate 或 SQLite 事务；提交时重新核对状态版本、lease epoch、目录身份及准入代际。collecting 阻止并发派发和暂停/停止提前释放目录。失败使用独立限时事务收口，重启将未完成采集标为失败，不重放旧读取或解除恢复保护。两次扫描仍只是观察一致性检查，不能声称文件系统与数据库绝对原子冻结；外部编辑器可在采集窗口之外改动，后续实际派发和验收仍须复核。
- `record_plan` 必须绑定选中任务、要求版本、前一计划版本、会话、上下文、源码与规则哈希。严格拒绝未知字段及大小写别名，外层继续拒绝重复键。计划包含任务预期、明确相对路径、依赖、关键验收点、验证方式、所需环境、独立审查内容及限制；这里只保存规格文字，不执行其中的命令。新建路径逐段检查敏感/排除策略，不能利用“基线里不存在”绕过保护；Windows 大小写别名、越界、根目录范围、链接和普通文件充当祖先均受到检查。
- 依赖保留启动时的显式边，只可新增选中范围内的关系，拒绝重复、自引用和依赖环；未完成的前置使计划 blocked。计划 ready 仅表示当前计划校验通过，不代表实施/验收已获放行。删除或改变既有验收点标记 review_required，后续无关修订也不能解除该状态；独立审查通过服务尚未实现。平台无法仅凭计划结构证明语义上满足用户全部要求，后续仍须任务对应关系检查及真实证据。
- 计划、任务阶段、进展计数、动作结果和事件同事务提交。相同决策重放或相同规范化计划不新增计划版本及业务版本；仅修订已有计划连续三轮进入 `needs_input/no_progress`。首次覆盖未规划任务视为本批规划进展，此计数尚不是涵盖实施、证据和等待条件的完整进展判定。领域拒绝接入已有两次有限纠正，每轮仍计预算；存储故障回滚整个动作并保留原建议，不能标成模型错误后提交半份计划。
- 基线正文读取按会话所拥有的清单授权，并校验正文哈希和大小，不能凭全局哈希跨项目读取。终态项目级联删除会清理会话上下文、计划和动作记录；全局去重的清单/正文目前保留，尚无垃圾回收、会话累计存储预算或存储回收界面，产品开放前须接入保留策略。当前每次采集上限不能替代设计中的每会话存储上限。

本批尚未实现完整环境指纹、可执行检查规格、首次写入前基线验证、实施/测试/独立审查执行、最终验收、独立资源登记、恢复解除保护、瞬时错误分类退避、完整角色配置及新页面。采集/计划失败或 lease 失效不会自动获得新的权限或恢复运行；存储恢复后的领域重试能力也不等于已经具备完整的故障自动恢复。下一步优先接入有界源码资料与实际实施派发、输入输出基线及角色执行边界，再接验证证据和独立审查，最终完成托管页面与启动入口。

## 17. 首期完整托管闭环

已接通默认后台 worker、独立 HTTP API 及完整角色执行链。托管会话开始后保存任务原文、依赖、认证配置、启动源码与项目规则基线，再由全局 Agent 逐轮观察并决策；不依赖页面持续打开。

- 调度、实施、独立审查均使用独立的一次性无工具 Claude CLI。服务端提供版本化输入，持久保存正常输出、下发内容、Run、事件及用量；不读取或编造模型隐藏推理。三个角色默认复用同一项目认证与模型档案，也可在创建时或暂停且执行收敛后分别配置认证档案、模型与思考强度，无需额外 Key。
- 调度动作包括读取资料、计划、实施、真实检查、独立审查、候选验收、暂缓/未解决、等待和提问。动作以会话/任务/要求/计划/源码/租约版本绑定，重复或迟到输出不能重新执行。
- 实施角色返回完整文件 edits 与原始 SHA-256；服务端通过明确 scope、受限目录句柄、文件哈希、规则与控制代际校验后应用。写入前保存变更日志，部分应用或恢复中的不明结果必须核对，不自动重放。任务实施/修复次数在真正 launching 时消费，测试不消费模型调用回合。
- 真实命令检查使用原生程序与独立参数，保留真实退出码、stdout/stderr 及进程身份；不将自然语言“运行通过”作为证据。验证令牌只能启动一次，相同快照/要求/规格不能靠修改检查 ID 无界重跑。临时故障采用有限次数与退避。
- 验证前后检查源码、原生执行程序、绝对启动脚本、锁文件以及嵌套依赖环境指纹；调度派发和动作应用前再次核对已通过证据的环境，避免测试返回后依赖变化仍被接受。环境变化将旧证据作废并允许同规格重新验证，保留实施事实。生成物和缓存不纳入源码清单；依赖目录中的 dist/build、项目内链接目标仍参与环境核对，项目外依赖链接明确拒绝，避免遗漏真正被运行的代码。
- 浏览器验收采用固定 Playwright 驱动，启动本轮独立测试服务、核对端口和就绪、使用全新浏览器上下文执行实际交互/断言，记录 pageerror、截图与报告，最后回收同一作业对象中的服务和浏览器。页面可读取校验哈希后的产物；端口占用、环境或浏览器缺失不得降级为假通过。
- 独立审查读取该任务原文、计划、源码、启动基线与实际证据，逐点返回结论。人工证据仅用于确需用户实际操作的 manual 验收点。按 evidence rowid 确定顺序，最新测试或人工记录之后必须再审查，不能依赖毫秒时间戳排序，也不能用另一个检查的成功掩盖不同规格的真实失败。
- `record_acceptance` 只保存 accepted 候选。后续写入使旧证据 stale，保留 implemented/accepted 事实；补测试与审查后，在同一最终源码快照上重新核对所有候选与依赖闭包，再原子写入 Task done、领域事件和终态。失败或暂缓任务明确进入未完成报告，其他独立任务可以继续推进。
- 实时读取外部前置状态与内容指纹，变化会唤醒等待、递增业务版本，并用证据 rowid 截止线作废旧依据；最终动作事务再次检查。连续读取已覆盖内容且没有新事实时执行 no_progress 门禁，新文件、清单分页和完整任务读取属于有效进展。
- 工作预算耗尽后进入 finalizing，尚未开始的任务 deferred，只验收已有成果；用户增加预算可以恢复由该预算门禁暂缓的任务。活动时间、全部模型回合、单轮时间、每任务修复、瞬时重试和最终验收预留均有后端门禁。
- 用户要求先持久保存再应用：延后模式等待当前执行收敛，立即模式中断当前回合后处理，随后递增相关要求版本、失效计划与证据，并取消旧 queued 工作项。用户本来 paused 时，补充要求不会偷偷恢复运行。
- 重启先保护目录及认领、核对持久命名 Job 并隔离旧代际。静默且无漂移时继续；目录/规则/中断写入需要核对时进入 needs_input。原 pause/stop 意图优先保留；显式控制可以终止已登记的自有命名 Job，核对静默后收口，但保留中断结果 unknown，不代办验收。终态 releasing 残留可由 worker 清理。
- 会话主要持久正文与源码 CAS、清单、规则及原始产物按 UTF-8 字节执行默认 2 GiB 的事务准入，超额写入回滚并暂停；页面可调 16 MiB–64 GiB，控制与收口额外预留 8 MiB。浏览器启动前预占产物容量，正常增长前检查数据盘与数据库盘余量。它限制逻辑内容，不是 SQLite 文件及磁盘总占用的物理配额，数据库页、索引、WAL 和备份仍需正常存储管理。源码 CAS 有垃圾回收。终态可显式清理原始截图/报告，结构化结果、哈希和 cleaned 标记保留；活动产物禁止清理。

## 28. 预算与用户控制交错复审修复（2026-11-03）
