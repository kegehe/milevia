# 快捷任务与命令系统

> 日期：2026-07-19
> 目标：让用户在项目 Claude 对话中以一次点击复用常用提示词和受控命令，同时保留当前会话、运行状态、审批、停止、用量和审计链路。

## 1. 问题与目标

当前用户每次都要在输入框重新编写重复任务，例如检查项目状态、运行测试、审查改动或生成交付说明。输入历史只能回看已经发送过的文本，不能整理、参数化、按项目复用或知道某个快捷项最近的执行结果。

本功能提供可管理的快捷标签。用户可以把常用提示词和命令保存为模板，在当前项目和会话中点击标签后发送；含变量的模板先要求补全变量。快捷标签不是另一个执行器，而是现有 Claude Conversation 的一个任务来源。

```text
选择快捷任务
  -> 解析变量
  -> 发送到当前对话
  -> 创建用户消息与 Claude Run
  -> 实时接收过程、审批、停止与使用状态
  -> 保存本次快捷任务执行记录
```

首期的单机 Web 控制台没有用户、团队或远程 Runner 模型。因此“全局”仅表示当前本机数据库内的所有项目，不应误称为跨用户共享；多人共享留待身份与工作区模型存在后实现。

## 2. 范围与非目标

### 2.1 本阶段实现

- 在对话左侧分别显示“常用提示词”和“常用命令”标签；
- 创建、编辑、删除、启用或停用标签；
- 点击标签即发送到当前会话；
- 使用项目和会话上下文渲染模板变量；
- 将一键任务复用到现有 Claude 消息、Run、审批、停止、WebSocket 和用量统计链路；
- 记录快捷任务的来源、渲染后内容、会话、Run 和结果，以便查看最近状态；

### 2.2 本阶段不做

- 浏览器或控制服务直接执行任意 Shell 命令；
- 快捷标签搜索、收藏、复制、排序、导入或导出；
- 独立的运行确认面板；点击命令标签本身即是用户的显式发送操作；
- 团队共享、角色、审批人、远程同步或云端快捷任务库；
- 定时任务、事件触发器、流水线编排和跨项目批量运行；
- 将快捷任务作为 Claude 的系统提示词或修改 Claude 原始会话配置；
- 在快捷任务内保存访问令牌、密码或其他秘密。

## 3. 设计原则

1. **复用一个运行入口。** 快捷任务必须进入现有 Conversation 的消息接口，不能私自创建第二套 Run、停止或事件通道。
2. **默认可检查。** 模板的默认动作是填入输入框；直接运行只能用于内容固定、风险低且变量完整的任务。
3. **命令经过 Claude 与现有权限策略。** 快捷“命令”向 Claude 发送明确指令，由 Claude 的 Bash 工具调用遵循当前 Conversation 的权限模式。网页不直接调用 `exec`。
4. **真实状态优先。** “运行中”“完成”“停止”“失败”来自关联 Run，不能由客户端猜测或使用超时模拟。
5. **先保证本机可用，再抽象共享。** 首期不提前引入用户所有权和团队权限字段；数据模型只预留稳定的作用域表达。

## 4. 快捷任务模型

### 4.1 类型与动作

| 类型 | 模板语义 | 可用动作 | 示例 |
| --- | --- | --- | --- |
| `prompt` | 面向 Claude 的任务说明。 | 点击后立即发送。 | 审查当前改动并给出风险。 |
| `command_request` | 要求 Claude 在当前项目执行指定命令并解释结果。 | 点击后立即发送，Claude Bash 调用仍遵循会话权限。 | 执行 `pnpm test`，总结失败并提出修复方案。 |
| `snippet` | 保留给已有数据的仅填入文本。 | 不在当前标签编辑器中创建。 | 缺陷复现步骤模板。 |

`command_request` 的模板仍然是普通提示词。推荐以固定前缀生成任务文本：

```text
请在当前项目中执行以下命令：
`pnpm test`

遵循当前权限模式；完成后总结结果。若失败，请定位原因，但不要修改文件，除非我继续要求。
```

这能让 Claude Code 按已有权限模式运行命令：`approval_required` 时 Bash 工具调用继续经过审批 Hook；`full_control` 时沿用用户已显式选择的跳过审批行为。快捷项本身不能改变该模式。把命令直接交给浏览器或新增 HTTP `exec` 接口会绕过现有权限边界，属于本阶段明确禁止的架构分叉。

### 4.2 作用域、分组与排序

快捷任务有以下可见范围：

| 作用域 | 规则 |
| --- | --- |
| `local` | 当前本机的任意项目都可用。 |
| `project` | 仅绑定的项目可用。 |

当前页面固定分为“常用提示词”和“常用命令”两组。标签保存在本机数据库中，可按本机范围或项目范围生效；当前 UI 不提供自定义分组、排序或搜索。

### 4.3 模板变量

首期只支持确定、可从当前页面得到的变量，不执行表达式、不读取任意环境变量。

| 变量 | 来源 | 无值时行为 |
| --- | --- | --- |
| `${project.name}` | 当前 Project 名称。 | 始终有值。 |
| `${project.path}` | 当前 Project 的受控路径。 | 始终有值，不在快捷列表完整展示。 |
| `${project.branch}` | 当前登记的 Git 分支。 | 替换为“无分支信息”。 |
| `${conversation.title}` | 当前 Conversation 标题。 | 替换为“新会话”。 |
| `${selection}` | 用户在变量面板中提供的文本。 | 阻止直接运行，要求填写。 |
| `${error}` | 用户在变量面板中提供的错误文本。 | 阻止直接运行，要求填写。 |

模板只做精确变量替换，未知变量或未闭合 `${...}` 视为配置错误。渲染前后都限制长度；变量值按纯文本拼入提示词，绝不将其当作 Shell 片段、HTML 或 SQL。

## 5. 页面与交互

### 5.1 对话页快捷条

快捷标签放在对话内容左侧，是当前项目的高频入口，不占用消息时间线。

```text
项目标题、运行状态、权限
----------------------------------------------
常用提示词  [+] [检查状态] [审查改动]
常用命令    [+] [clear] [运行测试]
----------------------------------------------
消息时间线 / 实时工具过程
描述希望 Claude 完成的工作...                 发送
```

- 空会话时也显示推荐快捷项，帮助用户开始任务；
- 正在提交请求时，标签暂时禁用；Claude 运行中仍可发送下一条提示词或命令，后端按会话顺序排队；
- 每个标签显示名称，并提供编辑入口；完整模板仅在编辑弹窗中显示；
- 对于需要 `${selection}` 或 `${error}` 的项，先打开紧凑变量面板，填写后立即发送；
- 首期快捷键：`Ctrl/Cmd+K` 打开面板，`/` 在输入区为空且未处于中文输入法组合状态时打开搜索。快捷键不能劫持用户正在编辑多行提示词的输入。

### 5.2 触发流程

```text
点击快捷项
  -> 已停用 / 不在作用域：不可触发
  -> 缺少必填变量：填写变量
  -> prompt：请求后端发送
  -> command_request：请求后端发送，由 Claude 根据会话权限执行
  -> 后端创建 Message、Run、ShortcutRun
  -> 前端显示运行状态并订阅既有 WebSocket
```

所有运行仍经过后端状态检查。持久 Claude 会话运行中，后续标签和输入会作为新的逻辑 Run 排队；非流式 Runner 仍会在会话忙碌时返回冲突。

### 5.3 管理页/弹窗

每个组标题的加号用于新增标签，标签右侧的编辑入口用于修改或删除。编辑表单包含名称、模板和启用状态；提示词保存为直接发送，命令保存为按当前会话权限请求执行。

保存前进行模板变量校验。危险命令不以关键词黑名单作为安全机制；需要更严格限制时，应使用审批模式或后续的受控 Runner 命令能力。

## 6. 数据模型与迁移

当前实现使用单机 SQLite；本功能沿用它。新增的记录与已有 `projects`、`conversations`、`runs` 使用外键关联。

```text
shortcuts
  id                   text primary key
  name                 text not null
  description          text not null default ''
  kind                 text not null              -- prompt / command_request / snippet
  template             text not null
  scope                text not null              -- local / project
  default_action       text not null              -- fill / confirm / run
  group_name           text not null default ''
  pinned               integer not null default 0
  enabled              integer not null default 1
  sort_order           integer not null default 0
  created_at           datetime not null
  updated_at           datetime not null

shortcut_projects
  shortcut_id          text references shortcuts(id) on delete cascade
  project_id           text references projects(id) on delete cascade
  primary key (shortcut_id, project_id)

shortcut_runs
  id                   text primary key
  shortcut_id          text references shortcuts(id) on delete set null
  conversation_id      text not null references conversations(id) on delete cascade
  run_id               text unique references runs(id) on delete set null
  rendered_content     text not null
  action               text not null
  status               text not null              -- accepted / completed / stopped / failed / interrupted
  created_at           datetime not null
  completed_at         datetime

shortcut_audit_events
  id                   text primary key
  shortcut_id          text references shortcuts(id) on delete set null
  action               text not null              -- created / updated / deleted
  payload              text not null default '{}'
  created_at           datetime not null
```

规则：

- `scope=project` 必须至少有一条 `shortcut_projects` 记录；`scope=local` 不写绑定记录；
- 删除快捷任务保留 `shortcut_runs.shortcut_id` 为 `NULL`，保留已经执行的内容和 Run 审计；
- `rendered_content` 必须保存，避免模板被之后编辑后无法解释历史执行内容；
- `shortcut_runs.status` 应由关联 Run 的终态同步，不能只依赖浏览器回调；
- 快捷任务执行审计写入 `shortcut_runs`；创建、编辑和删除等管理操作写入 `shortcut_audit_events`，不复用必须关联 Run 的 `events` 表；
- 增加索引：`shortcuts(scope, enabled, pinned, sort_order)`、`shortcut_projects(project_id)`、`shortcut_runs(conversation_id, created_at desc)`、`shortcut_runs(run_id)`、`shortcut_audit_events(shortcut_id, created_at desc)`。

本阶段不增加 `owner_id`。在身份系统实现时，可在 `shortcuts` 引入 `workspace_id`、`creator_id` 与可见性策略，并把现有本机数据迁移为默认工作区记录。

## 7. API 与服务编排

### 7.1 浏览器 API

```text
GET    /api/projects/{projectID}/shortcuts
POST   /api/shortcuts
PATCH  /api/shortcuts/{shortcutID}
DELETE /api/shortcuts/{shortcutID}
POST   /api/conversations/{conversationID}/shortcuts/{shortcutID}/preview
POST   /api/conversations/{conversationID}/shortcuts/{shortcutID}/run
GET    /api/conversations/{conversationID}/shortcut-runs?limit=20
```

`preview` 接收用户提供的变量并返回渲染文本，不创建 Message 或 Run。`run` 接收变量与动作；提示词使用 `run`，命令使用 `confirm` 表示此次点击是用户明确确认发送，二者都会进入同一消息与 Run 链路。

运行响应复用现有消息发送的结构，并附带快捷执行记录：

```json
{
  "message": { "id": "...", "content": "..." },
  "runId": "...",
  "shortcutRun": { "id": "...", "shortcutId": "...", "status": "accepted" }
}
```

### 7.2 事务与状态

`POST .../run` 的服务流程必须与现有发送消息同一事务边界：

1. 读取 Conversation、Project 和 Shortcut，校验快捷项启用状态与项目作用域；
2. 解析并验证变量，生成 `rendered_content`；
3. 对非流式 Runner 检查 Conversation 为 `idle`；持久 Claude 会话允许后续输入进入该会话队列；
4. 在同一事务创建用户 Message、`runs` 和 `shortcut_runs`，并将 Conversation 改为 `running`；
5. 提交后调用既有 Runner 启动逻辑；
6. Run 终止时将对应 `shortcut_runs` 更新为 `completed`、`stopped` 或 `failed`，并写入完成时间。

不要让快捷接口通过 HTTP 再调用自身的 `/messages` 接口。应把 `sendMessage` 中“创建消息与 Run、登记取消上下文、启动 Runner”的核心提炼为服务方法，普通发送和快捷运行共同调用。这可避免第二个请求、重复校验和审计记录与 Run 不一致。

### 7.3 实时状态与历史

网页继续订阅当前的 `/ws/conversations/{conversationID}`。运行状态、停止、审批和用量都来自现有事件流；无需为快捷标签增加第二个 WebSocket。

本功能必须继续兼容 `05-Claude对话上下文与使用状态`：快捷启动的 Run 与普通消息 Run 相同，因此用量、上下文、停止和审批统计天然归入同一 Conversation。

## 8. 权限、安全与数据处理

- 当前 Conversation 的 `approval_required` 与 `full_control` 是唯一执行权限来源；快捷任务不能提高权限或切换权限模式；
- `command_request` 仅构造 Claude 提示词。在 `approval_required` 模式下，命令实际发生时继续经过 Claude 的 Bash 审批 Hook；在 `full_control` 模式下，沿用当前产品已明确的跳过审批行为；
- 服务端验证快捷项 ID、项目作用域、变量键、模板语法、长度和 Conversation 状态；不能信任浏览器传来的模板文本、项目 ID 或渲染结果；
- 模板不支持任意文件读取、环境变量展开、JavaScript 表达式、URL 抓取或秘密占位符；
- 快捷任务内容、变量渲染结果和执行记录与普通用户消息同等处理，避免在 UI、日志或错误信息中额外泄露项目路径和敏感文本；
- 快捷任务的创建、编辑和删除记录在 `shortcut_audit_events`；有身份系统后补充操作者和工作区。

## 9. 当前验收

1. 用户可在左侧创建、编辑、删除、启用或停用常用提示词与常用命令标签。
2. 点击标签只创建一条用户消息、一个 Run 和一条 `shortcut_runs` 记录；Claude 运行中提交的后续内容按会话顺序排队。
3. 需要变量的模板在变量缺失时不能发送；填写后的内容与保存到用户消息的内容一致。
4. 快捷命令在 `approval_required` 模式仍显示审批；在 `full_control` 模式沿用既有跳过审批行为。标签不能改变权限模式。
5. 完成、停止、失败与服务重启中断会正确更新关联快捷执行记录。
6. 项目范围不匹配、停用或删除后的标签不能继续触发。
7. `go test -race ./...` 与 `pnpm --filter @auto/web build` 通过，并覆盖流式队列、停止竞争、关闭状态和重启恢复。

## 10. 后续能力

- 搜索、排序、导入导出、最近结果面板和更完整的标签管理；
- 在工作区和身份模型实现后支持团队库、角色与项目共享；
- 引入受控 Runner 命令目录、显式命令策略和独立命令执行实体时，再讨论真正的非 Claude 直接执行。
