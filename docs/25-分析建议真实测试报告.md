# 分析建议真实测试报告

日期：2026-11-11。范围：方案 §11 的分析、核实、编辑、再验证、防重、转任务和删除链路。

## 结论

在本机真实 Chrome、真实 HTTP 服务、隔离 SQLite 和已登录的 Claude Code 上，完成两次全分类分析及一次批量再验证，并实际操作编辑、单条/批量转任务、忽略恢复、筛选多选、取消和删除。已知计算错误能够发现，修复后判为失效，重扫未复活；已有有效建议、显式忽略建议和未完成任务的防重在该样例上成立。

真实测试发现并修复一处请求超时问题：扫描和再验证的同步引擎探测可能超过前端普通请求的 15 秒预算。修复后两条 POST 使用已有的 60 秒探测预算，仍不自动重试。注入 20 秒网络等待后，请求继续打到真实服务并成功返回 202，只提交一次。

链路通过不代表模型结论全部正确。本次也观察到模型核实前后不一致和部分理由不准确，见下文“质量观察”。

## 本次修复

1. `apps/web/src/lib/api.ts`：`POST /insights/scan` 与 `/verify` 进入已有 60 秒探测预算。依据是后端登记运行前调用 `requireInsightAgentReady`，探测预算为 45 秒；不增加模型轮次或自动重试。
2. `apps/web/src/api-timeout-retry.test.mjs`：验证这两条 POST 在 15 秒不会提前中止，60 秒耗尽时报告超时且各只发送一次。
3. `apps/web/src/conversation-layout.test.mjs`：全量前端测试暴露一条与本功能无关的旧源码断言，仍要求已撤掉的 taskQueue 折叠接线。检查现有布局 hook 后，更新为实际的 pane 状态、切换入口和 DOM 标志接线，保留折叠机制检查；没有为此修改对话页产品代码。

实际超时证据：12:42:50 左右发起再验证，后端日志 12:43:00 记录 elapsed_ms=10259，12:43:08 返回 409、elapsed_ms=17802；浏览器请求先被 15 秒预算中止，没有创建 verification。修复后重新构建，真实批量再验证正常启动并完成；20 秒延迟场景也通过。

测试过程曾错误预期超长依据应返回 400，检查源码后确认契约为截断。这是测试预期错误，已纠正为检查 2000 字上限并恢复原值，不据此修改产品行为。浏览器驱动也出现过选择器/执行会话超时，恢复后先读取真实服务状态再继续；未将工具超时视为功能失败或忽略未知结果。

## 质量观察与未覆盖边界

- 两轮核实对浮点小数候选的判断不一致：首轮因当前只有硬编码整数且没有输入入口而剔除，修复后重扫又保留为 bug，并在依据中承认需要改动数据才能触发。用户应结合可触达路径审阅，不能把“双轮核实”理解为已经运行过项目。
- 样式卡把省略显式 head/body 标签也作为“不规范”的理由；HTML 允许在符合条件时省略这些标签，这一子理由不严谨。卡片中无样式、文本列无法稳定对齐等其他事实与此不同。没有把该卡所有子结论计为人工确认。
- 故障/显示推断在模型依据中仍可能写“待运行验证”。测试只对预设总额错误及其修复做了独立运行验证，没有替模型把所有新增功能或假设故障都实现一遍。
- 本轮没有实际执行转出的任务到 done/cancelled，也没有验证任务托管自动修复后重扫。任务终态释放、并发事务、旧库迁移和响应预算由后端回归覆盖，应与真实模型/UI 证据分开理解。
- 未验证 Tauri 原生壳、Android 真机/中继、SSH/WSL 项目和其他模型引擎；窄屏 Chrome 只证明共用页面在该视口可用。
- 样例较小，本轮没有进行大型真实仓库的长时间扫描或负载压测。
