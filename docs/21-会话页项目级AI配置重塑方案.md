# 会话页项目级 AI 配置：档案管理入口重塑方案

> 日期：2026-08-08
> 状态：已实施
> 关联：docs/18（AI CLI 配置档案管理）、docs/20（按项目环境分发的 Agent Runner）

## 1. 背景与诉求

此前实现的"AI 配置档案（Agent Profile）"是一个**全局多档、独立页面**的管理系统：入口在独立的 `/agent-profiles` 页 + 新会话对话框里的下拉与"管理配置档案"链接。用户预期是**配置当前加载项目的** Claude / Codex 的 api、base_url、model，并且入口要放在**会话页合适的位置**，而不是埋在新会话对话框里。

两者是两套心智模型：

| | 原实现 | 期望 |
| --- | --- | --- |
| 视角 | 全局命名档案（档案后台） | 当前加载的项目 |
| 入口 | /agent-profiles 独立页 + 新会话对话框 | 会话页头部 |
| 术语 | 档案 / 停用 / 撤销 / 版本 / revision | 本项目 Claude / Codex 用什么配置 |

## 2. 决策

**确定为"前端重塑 + 后端只读聚合接口"，不动已验证的注入内核。**

理由：用户抱怨的是**心智模型与入口位置**，而不是加载物理。底层 `agent_profiles` 表、revision 快照、AES-GCM 密钥存储、`cli_managed` / `api_key` 注入逻辑均被 494 行测试与验收覆盖，重写它去迁就一个纯展示层问题会引入迁移与回归风险。项目的 `default_profile_id` 已经把"一个项目的一套 agent 配置"落成了现实，前端把它呈现为"Claude 卡片 / Codex 卡片"即完全吻合"项目级配置"的诉求。

## 3. 改动

### 3.1 后端：只读聚合接口（新）

`GET /api/projects/{projectID}/agent-config`

按项目 runner 汇总 claude-code / codex 各自当前生效的 profile，只暴露非敏感字段（model、baseUrl、authMode、是否默认），**绝不回显受管 Key**。`runnerManaged` 标识该项目是否本机可注入（SSH / Windows 调度 WSL 为 false）。

对应 struct `ProjectAgentConfigView` / `ProjectAgentEntryView`；路由注册于 `app.go`。

### 3.2 后端：默认配置对"其他 agent"优雅降级

`profileForNewConversationTx` 原先在项目默认配置与新建会话的 agent 不匹配时返回硬错误。由于 `projects.default_profile_id` 是**单列**，一个项目只能把一份配置设为默认；现在：

- **显式**选择的 profile 不匹配 target agent → 仍硬报错（这是用户明确的、应当暴露的选项冲突）；
- **默认回退**的 profile 不匹配 target agent → 优雅降级为使用 CLI 原有配置，而非让建会话失败。

> **已知限制**：`projects.default_profile_id` 是单列，一个项目只能把一份配置设为自动应用默认。若既配 Claude 又配 Codex，**最后保存**的那份成为自动套用默认，另一份需在新会话下拉里显式选择（不会报错，由上述降级兜底）。要让两个 agent 各自独立自动应用，需引入按 agent 拆分的默认列（后端数据模型变更，本次刻意不做）。弹窗已通过"项目默认"徽标如实展示当前生效者。

这样一边配 Claude、一边配 Codex 时，谁最后设为默认谁自动生效，另一边仍正常用 CLI 配置，不会被卡死。

### 3.3 前端：会话页项目 AI 配置弹窗（新）

- 新增组件 `apps/web/src/features/run/ProjectAiConfigDialog.tsx` + `project-ai-config.css`。
- 会话页头操作区新增"AI 配置"按钮（`ProjectConfigIcon`），与 历史 / 新会话 并排。
- 弹窗内为 **Claude / Codex 两张卡片**，各可编辑：模型、认证方式（使用 CLI 登录 / 受管 API Key）、base URL、API Key。
- 保存：复用现有 `PATCH /api/agent-profiles/{id}` / `POST /api/runners/{runnerID}/agent-profiles` 落库，再 `PATCH /api/projects/{id}/agent-profile` 设为本项目默认，新会话自动套用。
- "清除默认、改用 CLI 原有配置"按钮：把项目默认置空。
- 远端 Runner：弹窗显示只读说明，不提供编辑（本机不注入密钥）。

### 3.4 收敛旧入口

- 新会话对话框移除"管理配置档案"链接；下拉仍保留（会话级临时覆盖）。
- `/agent-profiles` 独立页保留路由（无导航入口、仅可深层链接），标题与引导文案改为"AI 配置管理 · 高级视图"，并指引用会话页 → AI 配置完成项目级配置。

## 4. 安全不变量（沿用 docs/18，未放宽）

- 聚合接口只读，不回显 Key；受管 Key 仍仅以 AES-GCM 密文落 `profile_secrets`。
- 只读接口不触发外连；运行时注入路径（`managedCLIEnvironment` / `runtimeProfileTx`）未改动。
- 远端 runner 仍不接收本机档案/密钥。
