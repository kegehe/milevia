# 工作区改动综合复查

本次检查当前未提交的 CLI 管理、任务托管、目标协议、工作区保护、普通 CLI 容器、附件和前端接线，以及桌面/目标辅助程序的构建依赖。修复继续保留工作区，不提交、不发布。

## 确认并修复的问题

1. **嵌入脚本变动未使构建缓存失效。** CodeBuddy ACP 探针通过 Go embed 编译进程序，但两个构建入口只跟踪 Go 源文件。目标辅助程序和桌面侧均加入 CJS 输入；桌面构建规则自身也加入指纹。新增脚本回归先失败、修复后通过。
2. **认证状态刷新复用了授权前的在途探针。** force 现在直接启动新探测；安装/修复后的失效操作同时脱离旧探测。旧探测仍唤醒原等待者，但只允许当前探测写回缓存，避免旧读数覆盖新结论。新增受控并发回归覆盖 force 和 invalidate，修复前均失败。
3. **远端技能路径按片段判断归属与来源。** 项目路径包含 plugins 或嵌套在另一 CLI 的技能目录时会被错误分类；同名原生技能也会受输出顺序影响。扫描和解析统一使用本地根目录表，按最深匹配确定归属，按显式根优先级覆盖；保留共享兼容根的多个 CLI 归属。新增回归覆盖误分类、越界目录和原生优先级，修复前失败。
4. **发布快照确认遗漏任务。** 持有查询游标时调用 Git，而 Git 工作区保护需要写入同一数据库，造成连接/锁等待。现在先收齐候选并关闭游标，再检查提交祖先关系。祖先检查仅将 Git 的退出码 1 视为“不包含”，其他故障直接报错，避免把验证失败当作跳过后确认成功。既有完整生命周期测试复现了漏任务；另加缺失提交回归，保证失败不改变快照状态。
5. **流式 CLI 提前报告会话结束。** 输出读取或排队帧写入失败时原先直接结束会话，此时容器可能仍在回收。现在保存终止原因、停止接收新回合，等待进程/容器收尾返回后统一发布终态；收尾失败仍由底层共享保护保留归属，不以逻辑 Done 证明静默。受控回归验证收尾返回前没有 Done，收尾后当前和排队回合均失败；真实容器夹具验证持久会话停止后的保护交还。

## 测试夹具修正

- 会话恢复用例使用实际本地 runner 标识，避免虚构 runner 被严格目标路由拒绝。
- 已结束编排任务的重新派发用例改用受控阻塞 runner，避免依赖本机真实 CLI 的安装、认证和完成速度。
- 流式读取错误夹具通过独立空测试子进程与受控容器收尾信号验证生命周期，不以当前测试进程充当被等待进程。
- 手机端推理强度操作已接入，但远程会话白名单测试仍期望旧的 11 项。补齐第 12 项的显式 POST、会话作用域、路径和处理器约束，避免仅放宽数量断言。
