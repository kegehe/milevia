# 对话页任务队列设计

## 目标

在项目对话页的左侧提供稳定的快捷操作和任务队列。用户无需离开当前对话即可看到任务状态、依赖阻塞和人工下发入口，同时继续以服务端状态机作为唯一执行裁决。

## 布局

桌面端将现有左侧快捷栏改为固定宽度的工作栏。

1. 顶部是一个横向可滚动的快捷操作行，合并现有常用提示词、片段和常用命令；每项保留现有发送、禁用、编辑和变量填写行为。
2. 快捷行下方是任务队列，默认只显示未完成任务，顺序为待验收、需处理、执行中、可下发、受阻，再按现有人工位置排序。
3. 每个任务行显示标题、优先级、状态和一个简短的依赖或最近执行提示。已受阻、执行中、已完成、已取消的任务不提供下发动作。待验收的任务可重新下发。
4. 队列的筛选为全部、待处理、执行中和待验收；已完成、已取消从默认列表隐藏，但完整任务页仍可查看。
5. 窄屏不挤压对话：快捷操作保留为横向滚动行，任务队列收纳为项目头部的“任务（数量）”抽屉。

## 快捷下发

任务行上的“下发”只出现在前端可初步判断为可下发的状态。点击后必须先读取 `GET /api/tasks/{taskID}`，打开简短确认层。确认层展示任务标题、描述摘要、优先级、当前权限模式和服务端返回的依赖检查结果。

只有当详情的 `canDispatch` 为真时，确认按钮可用。确认操作调用既有 `POST /api/tasks/{taskID}/dispatch`。服务端重新校验任务状态、前置任务和活动运行记录；冲突或状态过期时保留错误提示并刷新队列。下发成功后向现有对话追加消息、更新运行状态、关闭确认层并刷新队列。

点击任务标题或“查看全部任务”进入既有任务编排页；任务详情、编辑、验收和停止操作继续由既有任务编排组件处理。

## 组件与数据边界

新增 `TaskQueue` 前端组件，负责列表加载、筛选、紧凑行呈现、确认层和 10 秒轮询。它复用共享任务模型、状态标签和请求类型；任务详情仍由既有任务编排组件维护。

`TaskBoard` 与 `TaskQueue` 共享任务类型、状态/优先级展示及下发请求结果类型，避免两套状态映射。`Chat` 保持消息、运行状态和错误提示的唯一所有权，通过回调接收成功下发结果。

不新增或修改后端接口。列表接口已提供任务状态、依赖、阻塞项和最近运行记录；详情接口已提供服务端计算的 `canDispatch` 与 `blockReason`。

## 错误处理与可访问性

列表首次加载失败显示既有页面错误提示，轮询失败静默等待下一次轮询。确认层加载详情时禁用确认按钮并显示加载状态；详情读取或下发失败后显示错误，不伪造成功状态。所有状态文本有明确中文标签；任务行和操作按钮使用独立语义按钮，键盘可聚焦。

## 验证

前端构建必须通过。回归检查应覆盖：快捷项为横向布局；任务队列状态和受阻提示正确；不可下发任务没有可用下发按钮；确认层显示服务端资格；确认下发后消息和运行状态进入当前对话；窄屏任务抽屉不遮挡输入框。

## 约束

- 不提交 Git 提交。
- 保持人工创建、人工下发、人工验收。
- 不引入自动编排、自动启动、自动重试或新的任务状态。
- 服务端始终是下发资格的最终裁决。
