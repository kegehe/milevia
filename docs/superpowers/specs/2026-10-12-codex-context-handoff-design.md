# Codex 上下文交接设计

## 目标

为 Codex 会话提供应用级“压缩并新建会话”操作。该操作用一份可审阅的交接摘要创建新的会话，使用户能够主动缩短后续上下文，同时保留原会话和完整历史。

## 范围

仅处理 Codex 会话。Claude Code 继续使用其 CLI 提供的 `/compact`。现有“清空”保持为创建无上下文新会话的操作。

## 用户流程

1. 用户在空闲的 Codex 会话中选择“压缩并新建会话”。
2. 应用显示确认框，说明会生成交接摘要、保留原会话并打开新会话。
3. 后端创建一条持久化的交接操作记录，并在当前会话执行预定义摘要任务。该任务强制使用只读沙箱和结构化输出；提示词要求输出项目状态、已完成工作、待办事项、关键决策、约束和验证状态。
4. 摘要成功后，后端在短事务中创建同项目、同 Agent、同权限模式、同模型配置和同工作区的新会话，并持久化交接摘要。
5. 后端以该摘要作为新会话的首个真实 Codex 输入，完成新原生会话初始化。初始化任务同样强制只读并要求只确认已读取交接内容，不能调用工具或修改文件。
6. 初始化成功后，后端把交接操作标记完成；前端切换到新会话，刷新历史和用量。原会话仍可从历史中打开。

## 接口与状态

新增一个会话级 POST 接口，返回交接操作 ID；前端通过既有会话事件或操作状态轮询展示“生成摘要”和“初始化新会话”进度。模型调用不是数据库事务的一部分：只把会话创建、摘要持久化和操作状态更新放进短事务，外部 CLI 调用均在事务外执行。

新增交接操作记录，至少包含原会话 ID、新会话 ID、状态、摘要、失败原因和创建时间。状态依次为 `summarizing`、`initializing`、`completed`、`failed`。同一原会话同时只允许一个未终态交接操作。

交接摘要不能仅作为数据库中的消息写入。它必须作为新 Codex 会话的实际首个输入运行一次，否则下一轮 `codex exec` 无法获得该摘要。初始化完成后，摘要和确认回复都保留在新会话历史中。

前端将其视为会话转换操作，复用现有 `clearing` 状态和路由所有权保护：发送、停止、清空、快捷命令和工作区切换期间均禁用此操作。运行中的会话先通过现有停止确认流程结束运行。

## 失败处理

摘要生成失败时，操作标记失败，原会话保持可用。新会话创建或初始化失败时，操作标记失败，原会话保持可用；新会话保留为可恢复的历史项，显示“上下文交接未完成”，不得自动切换到它或删除用户可审阅的证据。用户可从原会话重新发起一次交接。

摘要与初始化任务使用固定服务端提示词和只读沙箱，且输出长度受限并经结构化校验。提示词禁止执行工具或修改文件；运行记录需标识为系统交接任务，避免被当作用户普通指令或快捷命令。

## 验证

后端测试覆盖：仅 Codex 可调用、同一会话并发请求去重、固定提示词与只读策略、结构化摘要校验、配置与工作区继承、新会话的真实初始化输入、各阶段失败后操作状态和不自动切换的行为。

前端测试覆盖：Codex 可见入口、其他 Agent 不显示、忙碌状态禁用、确认文案，以及成功后替换当前会话 Tab。
