# 工作区路径续审

用户继续要求复查后，重点检查了跨端工作区保护记录的查询、异常归属比较、认证读数及前端异步状态接线。本轮确认以下路径问题并修复；第 62 号记录中的 CLI / 附件修复继续保留。

## 确认并修复的问题

控制端对 Windows 盘符路径的比较区分大小写，与目标端 Windows 的目录规范化不一致。跨端保护记录保留请求路径，而本机路径通常已规范化，因此问题主要出现在跨端 Windows 路径或历史记录：同一目录换一种大小写访问后，保护仍然有效，但待核对操作列表可能为空；异常归属比较也可能漏掉同一目录的别名。

新增回归在修复前确认两个失败：盘符 / 目录大小写的重叠比较返回 false；数据库中存在父目录和子目录的保护记录，但恢复列表返回空数组。

修复措施：

- 只有明确的 Windows 绝对盘符路径采用与目标端一致的 Unicode 小写规范化；Linux 路径、路径中类似盘符的片段及 WSL UNC 视图保留大小写语义。
- Windows 路径的列表查询按连接和状态取得有序游标，在 Go 中逐项过滤并在匹配后计数；不使用 SQLite 仅支持 ASCII 的 lower / NOCASE，也不先截取无关目录的记录。结果集仍受原有上限约束。
- 非 Windows 路径继续使用现有 SQL 路径预过滤。保护令牌、目标身份校验与恢复时的实际退出确认规则保持原有行为。
