### 与目标目录结构的差异

早期架构文档（`docs/02`）规划了更细的分层，当前实际有以下差异：

- `apps/control-server/internal/` 下的 `modules/`、`runner-gateway/`、`realtime/`、`integrations/`、`shared/` 都是 `.gitkeep` 空目录，**实际业务代码全部在 `internal/app/`**。
- `apps/runner` 全是 `.gitkeep`，独立 Runner 服务未实现（Agent Runner 是 control-server 内的接口实现）。
- `apps/worker` 为空，异步任务服务未实现。
- `packages/` 下 `contracts`（openapi/proto）、`domain`、`ui`、`sdk`、`plugin-kit` 均为占位，无实际共享代码。
- `infrastructure/compose.yaml` 定义了 PostgreSQL/Redis/MinIO，但代码零引用，仅作未来迁移参考。

## 本地开发存储

| 服务 | 用途 | 当前路径 |
| --- | --- | --- |
| SQLite | 项目、会话、消息、运行、过程事件、任务、Git、配置档案等全部业务数据 | 桌面端：`<dataDir>/data/milevia.db`；开发态：`data/auto.db` |

数据库共 34 张表，涵盖 projects、conversations、messages、runs、events、tasks、task_runs、git_operations、agent_profiles、ssh_connections、shortcuts、orchestration_*、project_insights 等。

### 数据文件说明

- `milevia.db` / `auto.db`：SQLite 主数据库。
- `profile-master.key`：AI 配置档案的 AES-GCM 主密钥，用于加密存储 API Key 等敏感凭据。丢失会导致已存的密钥无法解密。
- `milevia.lock`：数据目录锁，由 `data_lock.go` 实现，防止多个 control-server 实例同时操作同一数据库。

## 本地开发启动

| 方式 | 说明 |
| --- | --- |
| 桌面端开发模式 | Tauri dev 模式，自动启动 sidecar 与 WebView。需本机 gcc（CGO）。详见 `docs/17`。 |
| 纯后端开发 | 直接 `go run` control-server，数据库落到 `data/auto.db`。 |
| 前端开发 | `pnpm dev` 启动 Vite dev server。 |

## 当前限制

- SQLite 单文件存储，适用于当前单人、本地阶段。多人协作、远程 Runner 或高并发队列出现后迁移 PostgreSQL、Redis 和对象存储。
- 无身份与权限系统（单机单用户）。
- 无独立 Runner 服务，AI 执行与控制平面同进程。
- 无 OpenAPI 契约，前端类型手写。
