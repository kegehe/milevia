# 38 · 一个手机连多台电脑（电脑同一时间只服务一台手机）

> 结论先说：**"一个手机只能连一台电脑"不是云端限制，而是手机端只存了一个令牌造成的**；
> 反过来"一台电脑只服务一台手机"今天**完全没有约束**（每配一次就多一个有效令牌）。
> 两件事都在手机端 + 云端各改一小块即可，不需要重做认证模型。

## 1. 现状（都有代码证据）

| 事实 | 证据 |
|---|---|
| 一个令牌**只能**看见一台电脑 | `userAuth` 用 token 查出 `instance_id` 塞进请求 context（`cloud-control/internal/cloud/server.go:1061-1090`）；`listInstances` 带 scope 时直接 `where instance_id=$1`（:1204-1229） |
| 手机端只存一个令牌 | `localStorage["milevia.cloud.token"]` 是单个字符串；读它的地方只有两处：`cloud()`（`MobileRemotePage.tsx:596-599`）与 SSE 建流（:1494） |
| 云端**允许**同一台电脑签发多个手机令牌 | 每配一次往 `cloud_access_tokens` 插一行（`claimPairingSession`，:741-799），**没有任何"已有手机"的检查** |
| 所以"电脑同时只能有 1 台手机"是**新增约束** | 同上：今天两台手机配同一台电脑，两个令牌都会被激活、都能用 |
| 手机上的「解除绑定」会踢掉**所有**手机 | `revokeInstanceTokens` scope=mobile：`update cloud_access_tokens set revoked_at=now() where instance_id=$1 and revoked_at is null`（:1265-1300） |
| 唯一的授权闸门是电脑端确认 | `agentConfirmPairing` 在一个事务里把该 pairing 的令牌 `activated_at=now()`（:629-667）；`userAuth` 要求 `activated_at is not null` |
| 云端**没有手机身份** | 表里只有 `token_hash / instance_id / pairing_id / activated_at / expires_at`，连手机名都没有 → "谁占着这台电脑"现在无从显示 |
| 换实例的状态隔离**已经在了** | instanceID 变化时清 `pendingTaskRef` / `realtimeMessagesRef` / `streamingMessagesRef` / `pendingNoticesRef`（:1133-1140）；`snapshotRevisionRef` 换实例取 -1 |

**好消息**：`cloud()` 与 SSE 是两个 choke point，13 处业务请求都走 `cloud()` —— 换"用哪个令牌"不需要动业务代码。

## 2. 目标模型

```
手机                                    云端                              电脑
 设备列表                                  cloud_access_tokens
 [{ 家里台式机, tokenA },                  (tokenA → instanceA)            每台电脑
  { 公司笔记本, tokenB }]        ──►        (tokenB → instanceB)     ◄──   同时只有 1 个
 当前 = A                                  + device_name                       有效手机令牌
```

两条规则：

1. **一个手机可持有多台电脑的令牌**，同一时间只有一台是"当前"（其余只是列表里的记录）。
2. **一台电脑同一时间只有一个有效手机令牌**：电脑端点「确认绑定」的那一刻，在同一事务里把该电脑上其它手机令牌全部 revoke —— 也就是**顶替**。

「顶替 vs 拒绝」是个产品选择，见 §6。

## 3. 服务端改动（cloud-control，改动很小）

1. **表结构**：`alter table cloud_access_tokens add column if not exists device_name text not null default ''`
   （沿用 `migrate()` 里已有的 `add column if not exists` 列表，:472-478）。
2. **claim 时上报手机名**：`POST /v1/pairings/{pairingID}/claim` 与 `POST /v1/pairings/claim` 的 body 各加
   一个可选 `deviceName`，写进那一行 `cloud_access_tokens.device_name`。
   —— 旧手机端不发这个字段，列默认空串，**向后兼容**。
3. **确认即顶替**：`agentConfirmPairing` 已有事务，在激活新令牌的同一事务里补一句：
   ```sql
   update cloud_access_tokens set revoked_at=now()
   where instance_id=$2 and revoked_at is null and pairing_id<>$1
   ```
   **必须在同一个事务里**，否则会出现"两台手机同时有效"的窗口（这正是要禁止的状态）。
4. **新增 `GET /v1/agent/bindings`**（agent 鉴权，返回该电脑当前有效的手机）：
   `select device_name, activated_at, created_at from cloud_access_tokens where instance_id=$1 and revoked_at is null and activated_at is not null order by activated_at desc`
   —— 给电脑端显示"当前绑定的手机"。
5. `revokeInstanceTokens` scope=mobile **语义不变**（1:1 之下"全踢"就等于"踢掉那一台"）。

> 不需要给手机做 device 表，也不需要把 `userAuth` 改成"令牌 → 设备 → 多实例"。那是"一台电脑连多个手机"才需要的东西，和我们现在的目标相反。

## 4. 桌面端（control-server relay + 页面）

1. relay：新增 `GET /api/remote/bindings` → 转发 `/v1/agent/bindings`。
   ⚠️ 白名单/鉴权是**两份**（`remote_control.go` 的路由白名单 + `remote_pairing_auth_test.go` 的会话令牌矩阵），
   新端点要同时进，否则会 401 或 404。
2. 配对卡片：
   - **已绑定**时先显示「当前绑定的手机」：名字 + 平台 + 绑定日期 + 最近同步时间，右侧「解除绑定」。
   - **生成二维码**时给出警告：`⚠️ 这台电脑同时只服务一台手机。确认绑定新手机后，Xiaomi 14 会立刻断开。`
   - 现在桌面端**没有任何解除绑定的入口**（只能从手机上解绑），补上。

   > **状态（2026-09-18）**：上面三条已全部实现，包括「平台」与「最近同步时间」——
   > 后者需要云端 `cloud_access_tokens.last_used_at`（由 `userAuth` 节流写入）与
   > `GET /v1/agent/bindings` 回 `lastUsedAt`。四档读数（旧云端 / 没同步过 / 在线 / 未同步）
   > 与"读数过期"那一档的判据、措辞、发布顺序，见 `docs/33-远程控制实施进度.md` 的
   > 「2026-09-18 电脑端显示"被哪台手机连着、它现在还在不在用"」一节，这里不再重复。
   > 页面形态也与本方案当初设想的不同：不再挂在配对卡片里，而是页头一颗胶囊 + 侧栏
   > 「已绑定手机」卡（见同一天的「方案 B 两栏工作台」）。
3. 手机名从哪来：`navigator.userAgent` 解析（Android WebView 里有 `SM-S9210` 之类）+ `Capacitor.getPlatform()`。
   拿不到就退回"Android 手机 / iPhone / 浏览器"，不要显示空。

## 5. 手机端改动

### 5.1 存储（含旧数据迁移）

```
milevia.cloud.devices = [{ instanceId, token, name, platform, boundAt, lastSeenAt }]
milevia.cloud.active  = instanceId
```

- **旧的 `milevia.cloud.token` 必须读一次并迁移**成单元素数组（旧包/新包会共存：用户可能上午用新包绑第二台，
  下午回退到旧包）。迁移后**不要立刻删旧键**，等新键稳定写入后再删，或者两者同时维护到下一个大版本。
- `token` state 保留，语义变成"当前设备的令牌" → 组件其余部分（13 处 `cloud()` 调用、SSE、快照）基本不用动。

### 5.2 两个 choke point

- `cloud()`：`const token = activeDevice()?.token`（读当前设备）。
- SSE 建流处：同上，并在**切换设备时主动断流重连**（现在是 `[instanceID]` 依赖驱动，只要 instanceID 变了就会重连，
  但重连时读的是新令牌 —— 要确认顺序：先落新令牌、再改 instanceID）。
- 401 分支：现在"删掉那个键 + 派发事件"。要改成**只标记那一台设备为失效**，并区分两种原因：
  过期 / **被另一台手机顶掉**（后者是新场景，界面要说人话："这台电脑已被另一台手机绑定，需要重新扫码"）。

### 5.3 切换设备 = 一次可复用的复位

切到某台电脑时依次：落 active → 复位 `instanceID / snapshot / selectedProject / selectedConversation /
commandState / refreshStatus / conversationTimeline` → `loadInstances()` → `loadSnapshot()` → 重建 SSE。
**已有的 per-instance 清理逻辑直接复用**（:1133-1140 那段就是为"换电脑"写的）。
`snapshotRevisionRef` 换设备必须取 -1（既有规则，别改）。

### 5.4 列表刷新

- 当前设备：保持 5s 轮询。
- 其它设备：30s 一次 + 打开切换面板时补一次。
- **每台用自己的令牌发探测请求**（`GET /v1/instances` 带各自 token → 各自返回 1 条，拿到 name/status/lastSeenAt）。
- 别为了"一次拿全"去新增聚合接口：把 N 个令牌塞进一个请求体，语义上等于把一组长期凭据集中暴露，不划算。N 很小（2~5）。

## 6. 手机端显示（推荐方案 A）

### 6.1 位置与形态

| 位置 | 显示 |
|---|---|
| 项目列表页，顶栏之下 / 刷新结果条之上 | **「当前电脑」条**：状态点 + 电脑名 + "在线 · 14:31 同步 · 3 个项目" + 右侧「切换 ▾」 |
| 点「切换」 | **底部弹层「选择电脑」**：每台一行（名字 / 在线离线 / 最近同步 / 绑定日期，当前那台带 ✓），底部「＋ 添加电脑（扫码配对）」 |
| 会话视图 | ⋯ 菜单**顶部一行非交互**：`当前电脑：家里台式机 · 在线`（菜单里已有"执行 Agent"这行先例） |
| 配对面板 | 改成**「我的电脑」**：已绑定列表（每行可解绑）+「＋ 添加电脑」；「使用校验码」降级成第二张卡 |

### 6.2 三条硬规则

1. **只有 ≥2 台时「当前电脑」条才出现** —— 单台时整行不渲染，老用户零感知。
2. **顶栏不动**：仍是"一行标题 + ⋯"。当前电脑不塞进顶栏（会挤掉标题，也违背既有定案）。
3. **切换中的过渡要说清楚**：切到离线/慢的电脑时，项目列表要显示"正在连接 公司笔记本…"，
   **不能直接落进"暂无项目"** —— 这是既有"空列表三种真相"规则的延伸（正在请求 / 请求失败 / 真的没有）。

### 6.3 为什么不是另外两种

- **B · 胶囊横排**：3 台以上要横滚（和任务分类栏同类的坑，那次已经吃过）；长名字被截断认不出是哪台；「添加电脑」还得另找入口。
- **C · 项目列表按电脑分组**：离线电脑读不到项目 → 列表空半截；项目一多页面很长；"当前在哪台"仍然模糊，
  任务队列 / 会话页还得另外找一个"当前电脑"。

## 7. 落地顺序（每步都能独立验证）

1. **云端**（Go 测试能覆盖）：schema + `deviceName` + 确认时顶替 + `/v1/agent/bindings`。
2. **桌面端**：relay + 「当前绑定的手机」+「解除绑定」+ 换绑警告。
3. **手机端存储层**：设备数组 + 迁移 + 两个 choke point（**这一步做完，多电脑在数据层就已经通了**，只是还没有 UI）。
4. **手机端 UI**：「当前电脑」条 + 切换弹层 + ⋯ 菜单那一行 + 配对面板改「我的电脑」。

发版顺序：**云端（push main 自动部署）→ 桌面端 → 手机端**。中间态是安全的：
云端先支持顶替，旧手机端仍按单令牌工作，只会表现为"被顶掉时 401 → 退回配对页"。

## 8. 需要拍板 / 风险

1. **顶替 vs 拒绝**（建议顶替）：
   - 顶替：扫码 + 电脑确认 → 新手机生效、旧手机立刻 401。换手机顺，但"手滑确认"会把旧手机踢掉。
   - 拒绝：已有手机时直接拒绝新配对，必须先在旧手机或电脑端解绑。更保守，但换手机变成两步。
   - 折中（推荐）：**顶替 + 电脑端确认时明确写出"会断开 Xiaomi 14"**，把风险摆在确认按钮旁边。
2. **手机侧多存几份长期令牌**：一台手机被物理拿到 = 多台电脑可控。缓解：设备列表里给「全部解绑」；
   令牌仍 90 天有效，被顶掉即失效。
3. **旧手机端兼容**：它只认单令牌。它绑的那台电脑被新手机顶掉后会 401，现有降级路径会把它送回配对页 —— 可接受，
   但建议提示文案里区分"过期"和"被别的手机顶掉"。
4. **远端命令发错机器的风险**：多电脑之后，"当前电脑"必须在**发消息/执行命令前**可见（这就是 ⋯ 菜单那一行的作用）。

## 9. 已实施（2026-09-17）

用户定案：**顶替**（不是拒绝）+ **方案 A**（项目页顶部「当前电脑」条，点「切换」开底部弹层）。
按 §7 的四步全部落地，另加了两处方案里没写、但落地时必须补的东西。

### 9.1 相对方案的增量

1. **云端多了 `POST /v1/agent/bindings/revoke`**：方案里只写了「电脑端显示当前绑定的手机」，
   但落地时发现电脑**没有任何主动解绑的入口** —— 现有 `/v1/instances/{id}/revoke` 只认手机令牌或
   运营者令牌（`authorizedInstance` 在 scope 为空时才放行），电脑端页面拿不到手机令牌。
   所以补一个"我是这台机器"就能断开自己手机的解绑端点。
2. **电脑端「当前绑定的手机」摆在生成二维码**之前（方案图里它和二维码并排）。
   理由是"点生成之前就该知道要顶掉谁"，生成动作在它下面更顺；为此桌面端配对卡片改成
   grid 三行：标题 / 绑定信息 / 生成按钮，之后才是二维码 + 右侧信息。

### 9.4 布局修订：两条合并成一条（2026-09-17 二轮）

首版落地后是**上下两张卡**：`.mobile-device-bar`（电脑名 + 在线/同步 + 切换）和
`.mobile-instance-status`（电脑名 + 状态胶囊 + 事件序号/时间）。用户实机看到后要求合并，规则三条：

1. **切换按钮放到「在线」下面** —— 右列做成竖排：状态胶囊在上、切换按钮在下（同一列、右对齐）。
2. **前面那颗运行状态点放到第二条的前面** —— 原来第一条左侧的圆点（在线/离线指示）挪到合并条的最左。
3. **样式取第一条那套** —— 合并条用 `.mobile-device-bar` 的绿底卡片，不再用实例状态卡的白底。

实现要点：

- 手机端只渲染**一条** `.mobile-device-bar`（`<section aria-label="当前电脑">`），内容＝
  `点 + 电脑名 + 事件序号/时间 + [右列：状态胶囊 → 切换]`；
  电脑端没有"我连了哪几台"的概念，仍用它自己的 `.mobile-instance-status`，**不跟着合并**。
- `showDeviceBar` → **`showDeviceSwitch`**：它现在只控制那颗按钮。卡片本身单台时也在
  （它就是原来的实例状态卡），但只有 ≥2 台可用设备时才给「切换」——没有第二台可切时
  留一颗点了没用的按钮只会误导。
- 右列里的 `.mobile-status` 要显式 `margin-left: 0`：它自带那条 8px 外边距是给旧的双列布局写的。

### 9.11 全面复查（2026-09-17 七轮，用户：「仔细检查所有实施和修改的代码」）

**复查手段**（不只读代码）：

1. **类名交叉扫描**（新脚本 `.tmp/audit-class-cross-ref.py`）：把 `mobile-remote.css` 里定义的 188 个类
   与 `MobileRemotePage.tsx` 里真正用到的类对撞一遍 —— 一次找出"删了 JSX 忘删样式"（孤儿）
   与"写了类名没样式"（断链）。

4. 跑全量回归 + 变异 + 核对脚本。

#### 查出并已修的问题（1 个真缺口 + 1 个我自己的错判）

1. **「我的电脑」面板没有焦点管理**（真缺口）。项目里"整页模态层"的焦点机制（搬焦点 + 背景 inert +
   关闭还焦点）此前**只挂在任务面板**（`tasksOpen`）上。设备面板是这一轮新加的浮层，漏了这一步 ⇒
   键盘 / 读屏用户打开面板后仍在背后那屏打转，`aria-modal="true"` 也名不副实。
   已照任务面板补上：两个 ref（面板 / 卡片按钮）+ 一个 effect + `.mobile-device-sheet:focus { outline: none }`。
   **依赖写 `[devicesOpen, mobileApp, mobileView]`** —— 面板渲染条件是
   `mobileApp && mobileView === "projects" && devicesOpen`，只挂 `devicesOpen` 时切视图会先卸载面板
   而 cleanup 不跑，背景永久 inert（任务面板的注释里已经记过这个坑）。
2. **我最初写的那条焦点断言判据是错的**：我断言"面板关闭后焦点必须回到卡片按钮"。实测 `focusBack=false`、
   焦点落在 `BODY`。查清原因后才发现这是**正确行为** —— 那条路径是「切换设备导致关闭」，
   `switchDevice` 会把 `instance` 置空、设备卡片连同按钮一起卸载，落点已经不存在了。
   现在断言分两条路径：
   - **切换设备导致关闭** ⇒ 只断言"inert 全部撤掉"；
   - **主动关闭（点 ×）** ⇒ 断言"焦点还给卡片按钮"（实测 `BUTTON | mobile-device-switch`）+ inert 撤掉。
   ⚠️ 教训：这一刀切的断言如果不查清就"修"，会被逼出一个错误的实现（比如硬把焦点塞回一个已卸载的节点）。

#### 查出的既有问题（**不是本轮引入**，报告不擅改）

| 位置 | 情况 | 建议 |
|---|---|---|
| `MobileRemotePage.tsx` `saveToken()` | **死函数**：只有定义、没有任何调用点（"手动粘贴令牌"的表单早已移除） | 确认是否还打算保留这条备用入口；不保留就连同断言/变异一起删 |
| `.mobile-token-form`（CSS 7 处） | 上面那个表单的孤儿样式 | 与 `saveToken` 一起处理（另有测试注释引用它作为"legacy 特异性陷阱"的例子，删时要同步改注释） |

| `.mobile-instance-select`（CSS 1 处） | 孤儿：旧的原生 `<select>` 已按"移动端不许用原生 select"的约定移除 | 可清 |
| 解绑确认框 / 编辑 / 删除 / 新建任务 / 快捷方式确认这 5 个对话框 | 都没有焦点管理（只有任务面板有） | 系统性既有缺口，建议单独一轮统一处理 |

现在看那个**前提是错的**。死代码上的防线不会出错，但会造成"这里有防线"的错觉，需要一并处理。

#### 确认**没有**问题的部分

- 云端 `agentConfirmPairing`：顶替与激活在**同一事务**里，先 `revoke` 该实例其它令牌

- 云端 `agentRevokeBindings`：agent 令牌鉴权；`where instance_id=$1 and revoked_at is null`（含未激活行）

- `mobile-header-menu-device` / `mobile-task-delete-modal` 无独立样式是**有意复用**

### 9.12 每台电脑一个「备注名」（2026-09-21，用户：「可以编辑每台连接电脑的名称，进行备注」）

**问题**：连了多台之后，列表上是 `DESKTOP-8F2K` / `LAPTOP-3C91` 这种出厂名 —— 用户认不出哪台是哪台。
需求是"给每台起的名字"。三个拍板项（用户选的都是推荐项）：**只存这台手机** / **每行一颗「备注」按钮** /
**单字段（一个备注名）**。

#### 数据层：`MobileDevice.alias`（`lib/mobile-devices.ts`）

三条语义钉死，否则很容易被后来的人"优化"坏：

1. **纯本地**：这是"这台手机上的这个人"的私有标注 —— 不上传云端，也**不**回写电脑端的 `deviceName`
   （那是手机报给电脑的名字，与"我给电脑起的名"是两件事）。
2. **只覆盖显示，不替代 `name`**：真名照旧留着，面板行里还要靠它说"原名是什么"。
3. **可以随时清空**：清空即回落 `name`，不是"名字变成空"。

配套两个纯函数，读写两侧共用同一个归一化：

- `normalizeAlias(raw)`：**先折叠空白**（移动端回车/粘贴会带进换行，直接存会让面板那一行被撑成三行）→
  **再 trim**（全空格 = 清空，不能存成看不见的空白名字）→ **最后按 `DEVICE_ALIAS_MAX_LENGTH`(24) 截断**
  （老数据、被手改过的 localStorage 都可能超长）。顺序不能换。
  **UI 的 `maxLength` 与存储侧必须用同一个常量** —— 两处各写一个数字就会出现"输入框允许 30 字、存进去只剩 24 字"。
- `deviceDisplayName(device)` = `alias || name || "未命名电脑"`。**这是唯一判据来源**，四处显示点都调它。
  参数收窄成 `Pick<MobileDevice, "alias" | "name">`：当前电脑卡手上只有云端的 `instance` + 本地的 `alias`，
  凑不出完整设备对象，不该为了调它去伪造 `token` / `boundAt`。

`addOrReplaceDevice` 加了一条**继承**：同一台电脑重新配对会拿到新令牌、旧记录被替换，
备注必须跟过来。这是本功能最容易漏的路径 —— "重新配对"恰恰是用户为了恢复连接（顶替、令牌过期）
最常做的操作，丢了备注等于让他白起一次名字。继承来源优先 `instanceId` 相同，其次令牌相同
（`instanceId` 还没从云端回填时只能靠令牌认人）。

#### UI：四处显示点 + 一层弹层

| 显示点 | 原来读谁 | 现在 |
|---|---|---|
| 当前电脑卡 | `instance.name`（**云端**） | `activeDeviceName` ＝ 备注 > 真名，在本文件上半段**合成一次** |
| 设备面板每行 | `item.name` | `deviceDisplayName(item)`，起了备注时上面多一行「原名 xxx」 |
| 面板行的两颗 aria-label / 解绑确认框 | `item.name` | 同上（确认框点的是显示名 —— 它要用户确认"断的是这一台"，用真名反而对不上列表里看到的那个） |
| 会话视图 ⋯ 菜单「当前电脑」 | `activeDeviceRecord.name` | 同上 |

**为什么必须合成一次**：卡片读的是云端读数、备注在本地设备表里，两处分开拼必然漏一处，
症状是"面板里改了备注、卡片上还是老名字" —— 用户会以为没生效，然后再改一遍。

两处不能省的细节：

- **云端读数没回来时，备注照样显示**（`<b>{activeDeviceName || "这台电脑的信息没读回来"}`）：
  备注是纯本地读数、不依赖 `/v1/instances`，这正是它比真名可靠的地方。但**副标题仍要说读数没回来** ——
  名字有了不等于这台电脑是好的，"有名字就说没事"会让人以为可以正常用（同"三种真相分开说"那条）。
- **备注弹层是设备面板之上的一层**（z-index 30 > 20），返回键链与 `leaveConversationView` 两处都要收，
  且返回键那条必须排在 `if (devicesOpen)` **之前** —— 排在后面时返回键会先把整个面板收掉、
  弹层还浮在项目列表上（与 `confirmUnbind` 同一个形状，之前实测过）。
  设备面板那个焦点 effect 的 inert 规则会跳过 `[role="dialog"]`，所以这张弹层天生留在可交互集合里。

#### 布局：动作列**竖排**（这是量出来的，不是审美）

面板行原来只有「解绑」一颗按钮。加「备注」时最自然的写法是并排，但 320px 屏上算不平：
面板内容宽 292px，并排时"名字 + 状态胶囊 + ✓ + 备注 + 解绑"会把名字挤到**不足 80px（约 5 个字一行）**，
而名字正是这一行存在的理由。改成 36px 宽的竖排动作列后，探针在 320px 下实测名字宽 **126px**（探针里钉了 ≥110px 的下限）。
顺序：备注在上（常用、无损）、解绑在下（危险动作留在最右下角），两档颜色也必须分开
（备注＝主色描边 `#b9dfcb`，解绑＝危险色 `#e3b3a9`），否则扫一眼会把"改个名字"当成"解绑"。

「原名」那行的选择器写成 `.mobile-device-row .mobile-device-row-who .mobile-device-row-origin`(0,3,0) ——
只写类名 (0,1,0) 会被上面的 `.mobile-device-row-who small`(0,1,1) 盖掉，
颜色淡不淡完全取决于书写顺序（本文件已经吃过一次这种亏）。

#### 验证

  只有令牌没有 instanceId 时也继承 / 新电脑不串味 / 旧存储没有 `alias` 键 / 被顶掉那台留着备注 / 显示名判据）。

  返回键**顺序** / `leaveConversationView` / 归一化只此一处 / 重新配对继承 / CSS 竖排与两档配色）。
- 浏览器探针 `.tmp/probe-mobile-pairing-page.mjs` 新增 2 段：备注的显示·改·清·不发请求（用**非 GET 请求计数**
  证明"纯本地"）+ 解绑确认框点名；以及走**真配对链路**（深链 → 云端确认）验"重新配对继承备注"。
  320px 视口下同时量了名字宽度与动作列方向。

  并**顺手校正了 5 条早已过期的锚点**（卡片 aria-label 分岔、状态灯的 `instance &&`、
  `setDevicesOpen` 的计数、`mobile-summary` 的期望值写反、CSS 锚点过短而命中两次）——
  每一处都在脚本里注明了"为什么变"，否则下次又会有人以为是自己改坏的。

**最终结果**：全量单测 **586/586**、`tsc -b` 0 报错、

### 9.13 备注名这一轮的复查（2026-09-21，用户：「再仔细检查所有实施和修改的代码有没有什么问题」）

复查手段与 §9.11 同一套（不重读代码）：① 类名交叉扫描；② 逐处审自己的 diff；
③ 先补"实现里写了、却没有任何用例走过"的分支，再谈对错；④ 跑全量回归 + 变异 + 核对脚本。

**类名交叉扫描**（`.tmp/audit-class-cross-ref.py`）：新增的 5 个类
（`mobile-device-row-actions` / `-row-alias` / `-row-origin` / `-alias-hint` / `-alias-clear`）
**零孤儿、零断链**；扫描列出的其余条目仍是已知的 id（`mobile-device-alias-title`）与

#### 查出并已修的问题（2 个真缺陷 + 1 个覆盖缺口 + 4 处文档/注释失实）

1. **动作列里两颗按钮右边缘错开 6px**（真缺陷，只在"起了备注"时出现）。
   `.mobile-device-row-unbind` 沿用了行内布局时代的 `align-self: center` —— 而它现在住在**竖排**动作列里，
   `align-self` 作用在**交叉轴**，列方向的交叉轴是**水平** ⇒ 这一句从"垂直居中"变成了**水平居中**。
   两颗按钮文案不等长时（有备注时是「改备注」3 字 vs「解绑」2 字）窄的那颗会缩在中间。
   实测（把 `align-self` 手工改回 `center` 跑探针，收尾按 sha1 还原）：

   | | left | right | width |
   |---|---|---|---|
   | 「改备注」 | 235 | 297 | 62 |
   | 「解绑」（center） | **241** | **291** | **50** |

   改成 `stretch` 后两颗都是 `left 235 / right 297 / width 62`。
   ⚠️ 这类错位**看截图不一定看得出**（差 6px），必须量矩形 —— 所以探针里加了这条检查，
   并**用上面那次手工回退证明它不是空转的**（改回 `center` 时探针 74/75，唯一一条 FAIL 就是它）。
   ⚠️ 注意它触发的是**本功能最常出现的状态**（有备注 ⇒ 按钮文案变 3 个字），而不是边角情况。
2. **截断按 UTF-16 码元会切坏 emoji**（真缺陷）。`normalizeAlias` 原来写的是
   `...trim().slice(0, DEVICE_ALIAS_MAX_LENGTH)` —— `slice` 切在第 24 个**码元**上，
   正好落在代理对中间时留下一个**孤立代理**：界面上是一个方块（�），存储里是一串再也拼不回去的
   坏数据。改成 `Array.from(collapsed).slice(0, 24).join("")`（按**码点**），并加一条单测
   （`🎉`×30 按码点截到 24、不留孤立代理、混合内容里 emoji 必须完整）+ 一条变异
   （退回 `slice` 必须被挡住）。
3. **备注弹层没有和它所属的面板绑死**（覆盖缺口 → 防御性修复）。它渲染在设备面板之上，
   但渲染条件只有 `aliasTarget`。今天**没有**可达路径能让面板先关掉（弹层背板盖满整屏、
   面板上的按钮点不到；`leaveConversationView` 与返回键链都各自收过它），所以这不是当下的 bug ——
   但"靠今天恰好没有那条路"不值得赌：将来任何一处新增的 `setDevicesOpen(false)` 都会留下一层
   浮在项目列表上的弹层。条件改成 `devicesOpen && aliasTarget &&`，并加断言 + 变异。
4. **`DEVICE_ALIAS_MAX_LENGTH` 的注释失实**。原文写"24 字正好是两行封顶（同 `.mobile-device-who b`
   的 `-webkit-line-clamp: 2`）"——`-webkit-line-clamp` 是**卡片**的规则，而**面板行没有 clamp**；
   实测 24 字在 320px 面板行里是 **3 行、行高 113px**。注释改成实测数字，并写明
   "卡片会截断、面板行完整显示"是两个刻意的不同取舍。
5. **`.mobile-device-row` 的注释还在写"只有两颗按钮（行主体 + 解绑）"**：结构已经变成
   [行主体] + [竖排动作列（备注 / 解绑）]。注释没跟着改，下一个读的人会以为「备注」是行主体的一部分。
6. **「原名」那条注释说"上面那条 `.mobile-device-row-who small`"** —— 那条规则其实定义在它**下面**。
   特异性 (0,3,0) > (0,1,1) 本来就**与书写顺序无关**，注释却把它说成顺序问题：改准之后，
   下一个人才不会以为"挪一下行序也没关系"。
7. **"四处显示点"的措辞不准**：实际是 **4 个位置、6 个调用点**（面板那一行里名字 + 两颗 aria-label）。
   `mobile-devices.ts` 与 `MOBILE-UI.md` / `MEMORY.md` 一起改准 —— 数字写模糊了，
