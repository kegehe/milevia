# 远程控制实施进度

## 已完成

- 电脑端 `control-server` 增加远程实例状态、事件 Outbox、命令幂等记录。
- TaskEvent 与远程 Outbox 在同一 SQLite 事务中提交。
- 支持快照、事件拉取、ACK、失败退避和命令最终状态查询。
- 本地 Worker 支持 `task.create`、`task.update`、`task.dispatch`、`task.stop`、`task.review`、`task.reopen`。
- 远程接口支持 Agent Token 隔离；未配置 Token 时仅接受回环请求。
- 新增 `apps/cloud-control` 云端 Control Plane 骨架，使用 PostgreSQL 持久化实例、命令和事件，支持 Agent WSS 与移动端 HTTPS API。
- 新增 `apps/agent` 电脑端 Agent：WSS 长连接、自动重连、本地 Outbox 上传、事件 ACK、远程命令转发和命令状态回报。
- 新增 Web `/mobile` 移动端控制页：实例选择、在线状态、项目任务快照、创建任务、下发/停止/验收操作。
- 增加二维码配对：云端生成 5 分钟一次性配对会话，电脑端 `/mobile` 可生成二维码，手机扫码后 claim，配对成功立即失效。
- 增加 PWA manifest、Service Worker 和移动端快照离线回退。
- 云端命令增加请求哈希校验，同一幂等键复用不同请求体时返回冲突。
- 云端命令创建会先校验实例存在；Agent 断开时实例状态更新为 `offline`；命令状态回报限制在合法状态并绑定实例，避免跨实例更新。
- 云端会在查询命令时自动标记已过期命令；事件/快照上报可自动登记首次出现的实例。
- Agent 连接关闭流程已改为上下文取消和连接关闭协同，命令监控协程不会向已关闭通道写入。
- 增加 Agent 通道取消单测、本地远程命令执行失败单测。
- 增加 Agent 配置与运行说明（`apps/agent/README.md`），并修正云端 HTTP Server 不因 HTTP 超时配置切断 WSS 长连接。
- 修复 Agent `https` 云端地址转换为 `wss`、写入失败检测、读写超时和心跳续期。
- 云端增加移动端 CORS、配对后实例级访问令牌、配对码随机生成；二维码 URL 不再携带配对码。
- 云端 Agent 凭据已改为按实例 ID 独立配置（`MILEVIA_CLOUD_AGENT_TOKENS`），并补充了云端优雅退出、WebSocket 消息上限、严格 Origin 校验和幂等命令重复投递保护。
- 云端命令保持 `queued` 直到 Agent 回报 `received`，断线重连可重新投递；事件批量上报增加格式校验和序号/事件 ID 冲突保护。
- 移动端增加快照定时刷新和命令状态轮询。
- 增加实例级移动端访问令牌和实例令牌撤销接口；二维码只携带配对会话 ID，不再泄漏配对码。
- `infrastructure/compose.yaml` 增加云端服务和环境变量示例。

## 单域名部署约定

- Web/PWA、Cloud Control API 和 Agent WSS 统一使用同一个公网 Origin，例如 `https://milevia.example.com`。
- 反向代理路由为：`/` -> Web 静态目录，`/health` 和 `/v1/*` -> Cloud Control（`/v1/agent/connect` 必须支持 WebSocket Upgrade）。
- `MILEVIA_CLOUD_APP_URL`、`VITE_CLOUD_URL`、`MILEVIA_CLOUD_URL`、`AUTO_REMOTE_CLOUD_URL` 应统一填写该公网 Origin；也可以在同源部署时将 `VITE_CLOUD_URL` 留空，让 Web 使用相对 API 路径。
- 已提供 `infrastructure/Caddyfile.example`；大陆服务器需要先完成域名备案和 HTTPS，境外服务器可先用于联调验证。
- 针对已有 Nginx 且不希望占用现有 80/443 的服务器，新增 `infrastructure/compose.server.yaml`（复用外部 PostgreSQL 网络、仅启动 Cloud Control）和 `infrastructure/nginx-keyanjia-8443.conf.example`（使用 `keyanjia.info:8443`，支持 HTTPS/WSS）。

## 2026-09-10 修复：配对链路可用性与可靠性

### 阻断级：桌面端无法生成配对二维码
- `/api/remote/*` 由 `remoteAgentOnly` 保护，desktop-api 模式下只认 `X-Milevia-Agent-Token`；而桌面页面只持有 `X-Milevia-Session`，因此"生成二维码"和"确认绑定"必然返回 401。
- 现在 `remoteAgentOnly` 对 `desktopPairingPaths` 白名单（`/api/remote/pairing`、`/pairing/confirm`、`/pairing/status`）额外接受 **desktop-api 模式下的有效会话令牌**；其余 relay 端点（outbox、commands、credentials 等）仍只认 Agent 令牌。已用 httptest 覆盖边界。
- 新增 `GET /api/remote/pairing/status` 转发云端配对会话状态，桌面端据此在手机提交后启用"确认绑定"，不再盲点。

### 安全：配对必须由电脑确认
- 原先 claim 即签发可用令牌，`userAuth` 不校验配对是否已确认，"电脑端确认"形同虚设。
- `cloud_access_tokens` 新增 `pairing_id` 与 `activated_at`；claim 写入时 `activated_at` 为空，`userAuth` 只接受已激活令牌；`agentConfirmPairing` 在**同一事务**中确认会话并激活令牌。升级时旧记录（`pairing_id=''`）自动标记为已激活，避免破坏既有配对。

### 安全：撤销语义与限流
- `POST /v1/instances/{id}/revoke` 现按 `scope` 区分：默认 `mobile` 只吊销手机令牌，**不再连带吊销 Agent 凭据**（原行为会把整台电脑踢下线且发布版无法自愈）；`scope=agent` 保留原语义。
- 为未认证端点增加按客户端 IP 的令牌桶限流：注册 30/min、配对 claim 30/min、配对状态 300/min（手机每 1.5s 轮询）。

### 可靠性
- 事件序号/ID 冲突不再断开 relay 连接：云端回 `event.reject`，Agent 通过 `/api/remote/outbox/fail`（`permanent=true`）丢弃该死信事件；数据库瞬时故障既不 ack 也不断连。
- 本地 outbox 增加投递预算上限（`maxRemoteOutboxAttempts`），耗尽的事件退出投递窗口，避免队首阻塞。
- Agent `publishCredentials` 改为每次连接建立后重试（原仅启动时执行一次）；HTTP 401（快照上传）也会触发限流重注册，不再只有 WebSocket 握手能发现凭据被吊销。
- Agent 凭据读写加锁（`credMu`），消除重注册与快照/心跳 goroutine 之间的数据竞争。
- 远程命令执行加 60s 超时，避免单条慢命令卡住串行 worker。

### 体验
- 二维码地址改为仅在绝对 http(s) 时生成，云端未配置 `MILEVIA_CLOUD_APP_URL` 时明确提示改用校验码，不再回退到 tauri 协议生成无效二维码。
- 云端 401 时前端清除失效令牌并回到配对流程；移动端新增"解除绑定"入口；扫码文案修正为"扫码 + 输入 6 位校验码 + 电脑确认"。

### 已知限制（未在本次处理）
- 移动端令牌无设备标识，撤销粒度为实例级，无法单独下线某一台手机。
- 二维码仍不携带校验码（避免经浏览器历史/代理日志泄漏），因此扫码后必须手输 6 位码；Android 未配置 App Links，系统相机扫码只会打开浏览器。
- 云端下行仍为 200ms 轮询数据库（未接入 Redis/LISTEN-NOTIFY）；权限位（`read:projects` 等）仍未实现。

- `go test ./...`（cloud-control，含新增的冲突分类、限流、Origin 校验用例）、`go test ./internal/app/`（control-server，含配对授权边界与 outbox 死信用例）、`go test ./...`（agent）、前端 `tsc --noEmit` 与 210 项单测。
- 配对确认的数据库交互由门控端到端测试 `pairing_e2e_test.go` 覆盖，需设置 `MILEVIA_CLOUD_TEST_DATABASE_URL`（库名须含 `test`）后运行。
