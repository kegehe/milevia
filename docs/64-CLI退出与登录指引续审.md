# CLI 退出与登录指引续审

本轮继续复查当前工作区改动，沿实际调用链检查 CLI 认证、管理后端、前端旧响应隔离、命令目录、用量转发，以及临时会话、终端和项目进程的工作区保护释放。结合第 61–63 号复查记录，只对有复现证据的新问题实施修复。

## 确认并修复

### 冲突建议临时会话退出后残留控制端占用

CodeBuddy / Qoder 的真实 streamJSONSession.Done() 只发送一次退出结果，不关闭通道。冲突建议的收尾却使用 for range 等待通道关闭：即使收到退出结果，也会继续等待；若主 select 已消费退出结果，收尾连第一次接收也无法完成。因此 releaseWorkspace 不会执行，控制端的内存操作占用和数据库保护记录残留，后续工作区托管准入会被阻止。底层普通 CLI 容器有独立的退出收尾，不能由此推断进程仍运行或所有写操作永久被锁住。

新增回归复用生产 streamJSONSession 的 Done / finish 行为，连接真实数据库和工作区准入入口。修复前，完成回合并发送退出结果后，准入仍返回 workspace still has active or unconfirmed execution。旧夹具在 Stop 时关闭 Done，因而没有暴露这一不兼容。

修复在主接收方记录是否已观察到退出；已经观察到时直接交还保护，否则在主接收方返回后只接收一次退出结果。没有用停止请求、回合完成或超时替代退出确认，并在 AgentSession 接口注明通道约定。

两种工具均覆盖完成、完成与退出同时就绪、回合失败、取消、发送失败和提前退出，检查退出前不能准入、退出后可以准入，并回读数据库确认操作记录已释放。

### 跨端登录指引遗漏实际命中的命令别名

目录后端可以通过 Cursor 的 agent 别名确认安装，但 Login 丢弃了该命令名，HTTP 层随后按主名生成 cursor-agent login。目标只有 agent 可用时，用户按指引会执行不存在的入口。

新增 HTTP 回归将目标执行面配置为只提供 agent，修复前确实返回 cursor-agent login；主命令可用的对照用例通过。修复后，目录后端保留探测成功的命令名，使用统一的终端指引函数返回 agent login；目录本身和其他工具的登录参数不被修改。

## 排除的误报方向

- 流式首次 Send 失败后，逻辑 Run 结束不代表工作区保护立即交还。托管会话及底层容器仍负责等待实际收尾，因此未将其报告为提前释放。
- 没有实现可选有界探测接口的模型目录适配器退回手动输入，是有意的兼容行为。生产 SSH / WSL 适配器均已实现该接口。
- OpenCode 的 step_finish 不会在当前解析链路中额外生成 result，不能假设一个不存在的后续事件会清空其用量累计。
- 认证信息无法识别时保留 unreadable，配置了凭据时保留 configured；未将这两种情况误判为未登录或账号登录有效。
