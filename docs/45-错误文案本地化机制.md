# 45 - 错误文案本地化机制

> 起因：2026-09-27，一条自动编排任务（标题「测试」、说明「你好」）失败后界面显示
> `任务执行失败，请查看任务日志后重试。：implementation produced no changes to commit`。
> 顺着查下去发现这不是孤例，而是"英文错误文案会流到用户眼前"这条链路上的一批缺口。
> 本文记录**修了什么**、**判据是什么**，以及**哪些事不要做**——因为其中几条是"改了不会报错、
> 只会静默失效"的类型，不写下来迟早会有人踩。

## 1. 英文是怎么流到界面上的

唯一的生成点是 `app.go` 里 `localizedErrorText` 的最后一个分支：

```go
return fallback + "：" + message   // fallback 是"任务执行失败，请查看任务日志后重试。"之类
```

所有下游都继承它，而且**下游全部不做二次本地化**：`task_runs.failure_reason`、编排作业的
`last_error` / `frozen_reason`、通知正文、`stream.error` / `run.failed` 事件、WS 回放、
手机快照。前端 `api.ts` 把服务端 `body.error` 逐字抛进 `Error.message`，约 100+ 处直接上
toast / 红条——也就是说 **Go 侧是唯一的门**（唯一例外是 `lib/timeline.ts` 那份镜像）。

另有一批**绕过这道门**的出口，本次逐个堵上（见 §4）。

## 2. `localizedErrorText` 的判定顺序（不可重排）

| 顺序 | 判据 | 为什么必须在这里 |
| --- | --- | --- |
| 1 | 若干硬编码哨兵（`project workspace is occupied`、`direct mode …`） | 分支名 `main` 会被判成"英文"，必须在翻译表之前拦住 |
| 2 | `translations` 精确匹配表 | 整句替换 |
| 3 | `context.Canceled` / `os.ErrClosed` → **空串** | 空串是**带语义的返回值**：读循环靠它跳过 `stream.error`，否则每轮被强杀的对话都会多一条假流错误 |
| 4 | `isInternalError`（`.go:` / `panic:` / `goroutine`）→ fallback | 内部实现细节不得外泄 |
| 5 | 含中文 且（含"失败" 或 无残留英文）→ **原样直通** | 见 §3 |
| 6 | `fallback + "：" + message` | 最后兜底 |

## 3. 两条承重规则

### 3.1 中文化后的句子必须保留"失败"（或"无法"）词面

直通判据是"含中文 **且**（含『失败』**或** 剔掉技术术语后没有残留英文）"。

进程退出这类错误的真实形态是「中文包装 + Go 的英文退出描述」，例如
`Claude 运行失败：exit status 1`——句子里必然有 `exit status`，所以只有那个"失败"分支能
让它直通。**把"失败"删掉（改成"未能完成"之类），用户立刻会看到一句
"任务执行失败，请查看任务日志后重试。：…"**：既指不到原因，又建议重试一件重试必然同样
失败的事。这条有测试守着（`TestRealLeaksNeverShowTheMisleadingPrefix`）。

### 3.2 Go 与 TS 是两份镜像，判据必须逐条一致

`apps/web/src/lib/timeline.ts` 的 `localizedErrorDetail` 是上面这套逻辑的**镜像**
（桌面端与手机端共用）。本次发现两者**已经不一致**：Go 有"含失败就直通"，TS 没有，
所以同一条错误在服务端不套前缀、在前端却会套一层。已对齐。

改任何一侧都要同时看另一侧，否则同一条错误在两个界面上的形态不同。

**2026-10-08 补：同一条判据里有两处容易看漏的偏差 —— 表与断词规则。**

起因是一条优化建议，说 TS 的判据"与服务端不等价（整词白名单 vs ≥3 连续字母）"。**那个
说法本身是错的** —— 服务端也是"≥3 个连续字母且不在表里"，`见 no 目录` 在**两侧都原样
直通**。照它去"收紧门槛"会把一处对的实现改坏，所以把实测结论记在这里：

- TS 那份原先写的是"先 replace 掉术语表、再看还剩没有 `[A-Za-z]{3,}`"。与 Go 的逐词扫描
  相比有两处实测偏差（都用真实 `localizedErrorText` 对拍过）：
  1. **表不同**：TS 那份多了 `NAT`/`localhost`/`wsl`（Go 表里没有）、少了 `NUL`。后果双向：
     `含 NUL 说明` 在服务端直通、在前端被套上"任务执行失败，请查看任务日志后重试。"；
     含 `wsl` 的则反过来。
  2. **断词规则不同**：Go 只按 ASCII 字母切词，`NUL2` / `NUL_x` / `JSON2` / `2NUL` 都含
     白名单词因而直通；而 JS 的 `\b` 把数字与下划线也算词字符，`NUL2` 既 replace 不掉、
     又整体是个 ≥3 字母段 → 被判成残留英文。实测这四个在服务端全是直通。
- **fix**：前瞻检查已改成与 Go 同构的逐词扫描（`value.match(/[A-Za-z]+/g)`，不用 `\b`），
  并按**两条链**分配白名单：

  | 链 | 用哪张表 | 为什么 |
  | --- | --- | --- |
  | `run.failed` / `error` / `turn.failed` / `stream.error` 的 detail | `allowedTechnicalTerms`（= app.go 那份 13 个词的逐词拷贝） | 服务端已经用 `localizedErrorText` 判过一道，前端再判必须同表 |
  | 工具结果（`tool_result`）、Codex 的 `item.*` 输出、聚合后的原始 stderr | `rawOutputTerms`（上表 + `NAT`/`localhost`/`wsl`） | 服务端在这几条链上**只搬运不本地化**（`tool_result`/`item.*` 原样转发；stderr 逐行发事件，`remoteNoticeTypesSQL` 刻意不含它）。口径由前端自定，取宽以免把可读中文（wsl.exe 的 UTF-16LE 主机侧警告）套坏 |

  之所以要拆两张表而不是统一：统一成窄表会把工具结果/原始 stderr 上那三条可读中文弄坏
  （那正是 3.2 之外唯一"允许"分叉的地方）；统一成宽表则让服务端已判过的文案在前端换表。
- **钉子**：`timeline.test.ts` 有五条用例。两张表都从源码里抠字面量比对 —— 窄表是**集合相等**
  （`deepEqual`，双向：少一个词、**多一个词**都算漂移），宽表是"只比窄表多 NAT/localhost/wsl"
  写死比较。另有行为抽查证明抠出来的字面量真的接进了判定（不是个已失效的常量），以及
  "NUL 放过 / `NAT`、`localhost`、`wsl` 在窄表上算残留 / 1~2 字母两侧都放过 / 数字与下划线
  紧邻白名单词仍直通 / 宽表不外溢到服务端已判过的诊断"。

  ⚠️ **单向比是不够的**：最初那起 bug 的成因恰恰是"多了几个词"，而"服务端每个词前端都放过"
  这种单向检查对它完全无感（第一版守卫就是单向的，被复查时发现并补成双向）。改任一边的表、
  断词规则或两张表的差集，都会红 —— 四种破坏形态都实测验证过。

### 3.3 字节预算

`insightRunErrorMessage` 会把消息按 **240 字节**截断（保留开头、切掉末尾）。而
`claudeExitPrefix` + Go 的退出描述（`exit status 137` 一类）+ 详情段
（`maxAgentDetailBytes = 180`）必须落在 240 之内，否则被切掉的恰好是最有用的末尾原因。

**注意中文是 3 字节/字**：一个看起来"很短"的中文前缀可能顶掉几十字节预算。
`assertClaudeExitMessageFitsInsightTruncation` 用真实前缀与真实上限算这件事，
不要去抄字面量——抄的话前缀换语言后那条断言会照旧通过，而它量已经不是真正发出去的那个串。

同理，给某条链上的文案换中文时，确认链上没有**裸字节切片**的截断点
（`truncateInsightLog` 是 rune-safe 的正例；`codex_runner.go` 里的是裸切片）。

**2026-09-29 实测补两条**（都在 `claude_runner.go` / `ssh_runner.go`）：

- **本地/WSL 形态的最坏值不是 `exit status 137`**（16 字节），而是 Windows 崩溃进程的十位
  状态码（`exit status 3221225477`，23 字节）：22 + 23 + 195 = **恰好 240**，余量为 0
  （`truncateInsightLog` 用 `<=`，所以还没被切）。`assertClaudeExitMessageFitsInsightTruncation`
  已改成按这个最坏形态算——原来按 POSIX 形态算，得出"还留了余量"的错误结论。
- **SSH 那条路径另有一套预算**。它的退出描述是 `ssh.ExitError` 的 `Waitmsg.String()`：
  除了 `Process exited with status 137 from signal KILL`（47 字节），还会拼上
  **远端给的** `. Reason was: <msg>` —— 长度不受我们控制，用 `%w` 就等于把预算交给远端。
  现在改成自己拼有界摘要（`sshExitSummary`：`exit 137（KILL）`，按**字节**限长）+
  按 `240 - 前缀 - 摘要 - 括号` 反推详情段**内容**额度（`claudeRunFailureDetailWithin`；
  额度算的是内容，括号另计，与 `maxAgentDetailBytes` 同一口径 —— 差这一步会让本地路径
  的详情段悄悄缩水，那条预算有测试钉着）。
  前缀本身也必须含"失败"（`sshClaudeExitPrefix`）：一次性路径原来写的
  `远程 Claude 退出：` 就是被 §3.1 那条规则挡下的漏网者（同一次改动里
  `StartSession` 已经改对了，`Run` 漏了）。

## 4. 绕过本地化的出口（本次已补）

统一走 `errorText(...)`：`git_conflict_suggest.go`（冲突建议的 ErrorMessage）、
`remote_control.go`（手机命令回执的 `result.error`）、`terminal.go`（终端 WS 控制帧的
`message`，**`code` 是协议字段不要动**）、`mcp_client.go`、`scheduled_tasks.go`
（写 `failure_reason` 的全部路径）。

桌面端 `apps/desktop/src-tauri/src/main.rs` 是**唯一一处纯英文直出**：tauri-plugin-updater
的错误经 `error.to_string()` 原样渲染在更新横幅上，连中文外壳都没有。现在统一走
`localize_update_error`，未命中时兜底成「更新失败：<原文>」，原文保留在括号里。

**2026-10-08 补：前缀必须跟着"出错的那一步"走。**

`localize_update_error(stage, …)` 现在收一个 `UpdateStage`（`Check` / `Download` /
`Install`），前缀分别是「检查更新失败」「下载更新失败」「安装更新失败」。原先只有一份
写死"检查更新失败"的文案，`background_download` 重试全败时也拿它填 `download.error` ——
**一次下载失败被说成检查失败**，用户会去查"为什么连不上更新源"，可检查其实早就成功了。

与更新无关的本地进程启动错误（`start_agent` / `start_sidecar`）另走 `localize_startup_error`：
它们同样是纯英文直出、同样需要中文外壳，但**不能借用更新那套判据**——"找不到 sidecar
可执行文件"说成"检查更新失败"是张冠李戴，而 `404`/`not found` 那条判据套到本地进程上会
产出「更新源上没有这个版本的文件」这种胡话。所以那个函数只套壳、不做语义分类。

同一处还修掉一个**死字段**：`UpdateDownloadRepr.error` 原先没有任何读者，静默下载失败时
界面只剩"后台下载未完成，点击后重新下载"。现在设置页描述、更新横幅、托盘面板三处都经
`downloadFailureReason()` 把它显示出来（横幅那一行是 nowrap + 省略号，所以同时挂 `title`）。
判据在 `update-view.ts`，钉子见 `update-view.test.ts`（"后台下载失败的原因要显示出来"）
与 `UpdateBanner.test.mjs`。

## 5. 手机端：码优先，文案只作兜底

手机端 `classifyGitFailure` 隔四跳只能拿到一句文案，原先按**英文子串**匹配
（`Git state changed` / `no longer available` / `no eligible Git changes` / `runner_offline`）。
这是错的判据：文案会被翻译、会被改措辞，改了那边不会报错，只会**静默失效**
（docs/41 §15.1 记录过一次真实事故——"工作区被占用"那一档在真实链路上永远不命中，
而单测喂本地化之前的英文，照样绿）。

现在这些种类都有稳定码（`httpErrorCode`）：`workspace_occupied`、`active_runs_present`、
`git_state_changed`、`git_paths_gone`、`git_no_changes`、`runner_offline`。
`FAILURE_MATCHERS` 降级为**兼容旧服务端**的兜底层，纪律是"要加新种类先去服务端加码，
不要往 needle 表里加条目"。

两个方向的钉子：`TestGitFailureCodesSurviveTheRelay`（服务端侧：码经 `writeError` →
中继答复穿到底）、`mobile-git-request.test.ts` 的
"the new git failure codes classify without any matching text"（客户端侧：文案认不出也要判对）。

加了码之后，`docs/41` §12 第 5 条登记的"两处共享英文"就不必再改文案了——**判据换了，
文案可以保持英文不动**（旧客户端与旧云端仍按它匹配）。

## 6. 明确不做

- **不做后端全量中文化**。源码里有约 738 条纯英文叶子字面量 + 390 条 `%w` 包装，
  分布在 52 个文件。本次只收口"结构性缺口 + 实测漏出的那一类"。真要做，机制上应选
  **改写源码字面量**而不是扩翻译表——精确匹配表对带 `%w` 的包装串**原理上必然漏**
  （`app.go` 里那条 `Contains` 兜底的注释已经承认过一次），而且漏得静默。
- **不引入 i18n 框架**。只有中文一种语言；i18n 的 key 缺失默认回退原文，恰好是要消灭的东西。
- **不做全局 `strings.ReplaceAll` 短语层**。它作用在渲染后的整串上，而整串里混着外部工具
  输出（git / npm / ssh / CLI 的报错是用户拿去搜索的唯一线索，必须原样保留）。
  缺一条会产出"中文搜不到、英文被切碎也搜不到"的半汉化串，比现状更差。
- **不翻译 CLI 原生 JSONL 事件文本**（`sink.Event(envelope.Type, line)`）。Go 层没有解析
  那行文本的结构，硬翻要重新解析 CLI 的私有协议，会随 CLI 版本碎掉；而终结性失败已经有
  结构化路径。
- **不删 `fallback + "：" + message` 这个出口**。它是用户拿到**可搜索原始线索**的唯一出口。
  正确做法是让前缀尽量少出现（靠中文化提高直通率），而不是删掉出口。
